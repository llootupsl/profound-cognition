```

         Typst → output/document-renderer.md
         Penrose DSL → protocols/illustration-generation-protocol.md（Penrose 集成，无独立渲染器文件）

Step 4: 分批落盘 + 合并（write-while-research protocol）
   a. 每完成一个章节集群（约8000-22000字，对齐 SKILL.md §0.1 各部分字数地板）：
      - 立即追加写入 out/report_partNN.md
      - 从上下文释放全文（仅保留≤300字摘要 + 章节锚点）
   b. 所有章节生成完毕后：
      - 合并：按大纲顺序拼接 report_part*.md → report_full.md
      - 重建全局目录 / 页码 / 交叉引用编号
   c. 然后移交至 docx/PDF 导出
Step 5: 生成 Typst 源码 + HTML+CSS（供 Typst）+ exhaust_retry_output（Markdown）
Step 6: CLI 编译验证：
         Typst → typst compile report.typ → report.pdf
         Typst → weasyprint HTML(string=html).write_pdf()
Step 7: Word (.docx) 导出（pandoc → python-docx → md+guidance 三级路径）
Step 8: 编译失败 → exhaust-retry 至 exhaust_retry_output；
         编译成功 → 输出 PDF + exhaust_retry_output 双通道
```

### 默认精排链（v4.1.3 强化）

research_report 默认交付物为 **PDF + Word (.docx) 双格式**（对齐 SKILL.md G6 硬门控「research_report 默认 PDF 与/或 .docx」）。两条渲染链均为强制默认路径，不得仅输出 Markdown 作为最终交付物。

| 渲染链 | 优先级 | 触发条件 | 交付物 |
|--------|--------|----------|--------|
| Typst → Typst PDF | 默认（主） | research_report 默认路径 | report.pdf |
| pandoc → Word .docx | **默认（主，v4.1.3 强制）** | research_report 默认路径，与 PDF 并列强制产出 | report.docx |
| HTML+CSS → Typst PDF | 穷尽重试替代 | Typst 引擎不可用 | report.pdf |

| Markdown + 指南 | **最终穷尽重试替代（非交付物）** | pandoc 与 python-docx 均不可用 | report.md + docx 生成指南（须明确标注为过渡产物，非最终交付物） |

**铁律（v4.1.3 新增）**：

## Step7: Word (.docx) 导出（v4.1.3 强制默认交付物）

### 概述

**Word (.docx) 是 research_report 的强制默认交付物之一**，与 PDF 并列（对齐 SKILL.md G6 硬门控）。本步骤与 Step5/Step6 同级强制执行，不得跳过、不得降级为可选附加步骤。生成 .docx 满足学术/专业场景下的编辑、审阅与协作需求。

### 强制执行条件（v4.1.3 新增）

- 本步骤**不得**被标记为可选、附加或"穷尽重试保底"
- 仅当用户在 T01 输入中明确指定"仅要 PDF"或"仅要 MD"时，本步骤方可跳过，并在交付注册中标注 `docx_skipped_reason: "user_explicit_request"`
- 任何其他情况下跳过本步骤 = G6 硬门控不通过 = 不得交付

### 输入

| 输入来源 | 格式 | 优先级 |
|----------|------|--------|
| Step5 产出 | HTML+CSS | 优先（pandoc 可解析 HTML） |
| Step6 产出 | 合并 Markdown（report_full.md） | 备选（pandoc 可解析 Markdown） |

### 三条路径

| 路径 | 引擎 | 优先级 | 触发条件 |
|------|------|--------|----------|
| pandoc 转换 | pandoc | 主路径（primary） | pandoc CLI 可用 |
| python-docx 生成 | python-docx | 穷尽重试替代路径 | pandoc 不可用 |
| Markdown + 指南 | 纯文本 | 最终穷尽重试替代 | python-docx 不可用 |

#### 路径一：pandoc（主路径）

将 Step5 HTML+CSS 或 Step6 Markdown 通过 pandoc 转换为 .docx，使用参考模板控制样式：

```bash
pandoc report_full.md -o report.docx \
  --reference-doc=template.docx \
  --toc --toc-depth=3 \
  --from=markdown --to=docx
```

#### 路径二：python-docx（穷尽重试替代路径）

pandoc 不可用时，通过 python-docx 库程序化生成 .docx，逐章节写入，手动控制封面、目录、表格、图表等元素。

> **v4.1.5 新增强制规则**：使用 python-docx 路径时，**必须优先使用 skill 自带的模板文件**：
> 1. 检查 `output/docx-templates/build_docx.py` 是否存在——若存在，**必须**基于该脚本进行修改或直接调用，而非从零编写临时脚本
> 2. 检查 `output/docx-templates/reference.docx` 是否存在——若存在，**必须**作为 python-docx 的样式参考模板（`Document('reference.docx')`），而非使用默认空白模板
> 3. 若自带模板不存在，方可从零编写，但必须在交付注册中标注 `docx_template_used: "none_builtin"`
> 4. **禁止使用一次性临时脚本**——生成的 .docx 转换脚本必须保存到 `output/` 目录下（如 `output/build_docx_v{version}.py`），便于后续复用和质量审计

#### 路径三：Markdown + 指南（最终穷尽重试替代，非最终交付物）

pandoc 与 python-docx 均不可用时，输出 Markdown 文件并附带 docx 生成指南（含 pandoc 命令模板、参考模板说明、python-docx 脚本模板），供用户自行转换。**此路径产出的 MD 文件为过渡产物，非最终交付物**——必须在交付注册中标注 `docx_status: "pending_manual_conversion"` 并在用户对话中明确提示"docx 需用户手动转换"。

#### 自动目录（TOC）

- 自动生成目录，≥ 3 级标题深度
- 页码正确对应正文内容
- 目录项可点击跳转（pandoc 默认支持）

#### 页眉页脚（Header + Footer）

- 页眉：报告短标题（奇偶页可不同，奇数页=报告标题，偶数页=章节标题）
- 页脚：页码 + 总页数（"第 X 页 / 共 Y 页"）

#### 图表编号

- 所有图片以"图N"连续编号（全文统一编号，N 为阿拉伯数字）
- 每张图对应完整图注，包含：编号、标题、数据/来源标注、说明文字（≤2 句）

#### 中文三线表样式

- 所有表格采用中文学术三线表格式：
  - 顶线（粗线，1.5pt）
  - 栏目线（细线，0.75pt）
  - 底线（粗线，1.5pt）
  - 无竖线、无行线
  - 表头加粗居中
  - 表注以脚注形式置于表下方

## 正文洁净与去脚手架（强制，违反即被输出卫士退回）

最终报告**面向读者**，正文是一篇连贯的学术 / 专业长文，**不得**暴露任何内部"脚手架"：

- **无节点号**：正文与标题中不得出现 T01 / TM03 / T_* / I01 等节点编号；章节一律用语义化标题（如"系统动力学分析"），不写"（T22）""TM01 节点"。
- **无门控 / 阶段 / 层代号**：不得出现 Gate-α / Gate-终、Phase、L1–L9 等。
- **无内部字段**：不得出现 context_package、NRSF、confidence_rating、route / deps / tok 等。
- **无内置算法 / 工具 / 库名**：科学层与图表的描述须用**通俗方法学语言**——写「系统动力学仿真显示…」「因果推断表明…」「情景推演给出三条路线…」，**不得**点名 仿真引擎 / 因果识别 / 异质效应估计 / 贝叶斯推断 / 本体构建 / 语义映射 / 知识图谱嵌入 / 图数据库 / Typst / Typst / Mermaid 等实现工具。
- **来源仍需透明**：以上"去脚手架"仅针对**内部编排与实现细节**；对**外部事实证据**的引用、数据来源、参考文献必须如实标注，不得隐去。

渲染完成后，全文交 `T20_output_guard` 分块扫描；命中任一项 → 清洗 → 重渲染 → **复扫至 clean** 方可交付。

### 参考文献与证据附录强制规则（v4.1.4 新增 — 修复参考文献/配图被放在"补充文件"中的问题）

> **铁律**：参考文献、证据附录、配图**必须**作为主报告结构的独立章节，在渲染过程中一次性生成。**严禁**事后补充到单独的"补充配图与参考文献"文件中。

1. **参考文献章节**：
   - 必须作为主报告的独立章节（位于 §8 之后、证据附录之前）
   - 必须在渲染过程中随正文同步生成——每引用一个来源即记录到参考文献列表
   - **不得**在正文渲染完成后另行创建"补充参考文献"文件
   - 格式统一为：`[序号] 作者. 标题. 期刊/出版社, 年份.`
   - 数量 ≥ 30 条，覆盖研究涉及的全部领域

2. **证据附录章节**：
   - 必须作为主报告的独立章节（位于参考文献之后）
   - 包含关键证据链、数据来源说明、方法论细节
   - **不得**放在单独的"补充内容"文件中

3. **配图生成规则**：
   - 配图必须在渲染对应章节时**同步生成**，嵌入正文相邻位置
   - **不得**在正文渲染完成后另行创建"补充配图"文件
   - 若渲染时 Mermaid/SVG 生成失败，立即在该位置标注 `[图N待补：{图标题}]` 并在穷尽重试中补齐，**不得**推迟到单独的补充阶段

4. **硬门控自检报告**：
   - G1-G6 硬门控自检是**执行轨迹**，不是成品内容
   - **严禁**将硬门控自检报告作为章节嵌入最终交付物中
   - 硬门控自检结果仅记录在执行账本中，对用户不可见

### 用户额外需求章节处理规则（v4.1.4 新增 — 修复附录结构定义不清问题）

当用户在 T01 输入中提出额外需求（如"包含报名内容模板""包含操作手册"等）时：

1. **额外需求章节定位**：用户额外需求的内容应作为「实战附录」章节，位于证据附录之后，与学术附录区分
2. **章节命名**：使用语义化标题（如「附录A：冠军级报名内容完整模板」「附录B：TRAE SOLO完整操作手册」），**不得**使用内部代号
3. **字数计入**：实战附录字数计入总字数，但不计入 §1-§8 各部分字数地板
4. **结构完整性**：实战附录必须包含完整可执行的内容（如报名模板需可直接复制使用，操作手册需含具体命令），不得停留在概念描述层面
5. **与主报告的关系**：实战附录是主报告的延伸，不是独立文件——必须嵌入主报告文件中，**不得**作为单独文件交付

### 扩写禁止事项
1. **不得复述前文**——新段落不得用不同措辞重复前面已陈述的观点或结论
2. **不得堆砌同义词**——不得通过同义替换方式对同一概念反复展开（如"结构性矛盾→体制性困境→制度性障碍"）
3. **不得填充常识**——不得用读者已知的常识性背景填充字数（如"随着互联网的发展..."类陈述）
4. **不得重复相同结论**——不得在同一篇输出中多次以不同形式重申同一结论
5. **不得用不同案例讲同一道理**——若两个案例说明的是同一个论点且无新增分析维度，只保留一个
6. **不得用"进一步/更深入/值得注意"开头**——此类过渡词暗示即将复述前文或做无实质扩写
7. **不得无证据扩写**——任何扩展性陈述必须有对应证据、案例、数据或逻辑推导支撑
8. **不得无结构地列举**——禁止"A、B、C、D..."式无分析、无层次、无优先级的平铺列举

**元规则**：成品字数由"主线论证完整性"决定，不为达到特定字数而触发任何扩写。字数是结果不是KPI。

## 研究报告 7 步自然文风结构（M13，移植自母提示词 §6.8）

不同于渲染准备（剥离内部标记等），此为研究报告的写作结构。

| 步骤 | 名称 | 写作目标 | 禁止事项 | 自检 |
|------|------|---------|---------|------|
| 1 | 引入 | 用具体现象/问题开头，不用"本文旨在"开篇 | 禁止教科书式"A的定义是..."、"随着...的发展" | 前200字是否有具体的人/事/数据？ |
| 2 | 全景 | 建立问题的时间/空间/概念坐标系 | 禁止在第二步深入任何单一维度 | 读者能否用一句话说清"这个问题在哪？" |
| 3 | 逐层剥开 | 从表层→机制→结构→认知，每层追问"为什么" | 禁止仅描述现象不给机制解释 | 每层是否至少追问了3层"为什么"？ |
| 4 | 横切 | 引入副线/对比视角（M9 第2-3名） | 禁止横切后不回主线 | 横切段落是否不超过全文15%？ |
| 5 | 时间纵深 | 用时间演变链追问"为什么会变？" | 禁止仅罗列时间点 | 演变链是否≥5个节点？ |
| 6 | 反事实 | 引入对立面/反证/边界 | 禁止无实质反证（"也有人认为..."） | 反证是否有具体出处？ |
| 7 | 收束 | 回到问题原点，给出边界完整的结论 | 禁止给出"万金油"结论 | 结论是否包含"在什么条件下不成立"？ |
