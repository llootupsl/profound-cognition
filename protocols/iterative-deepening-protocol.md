# I01 迭代深化协议

## 1. 概述

I01 迭代深化节点插入在 T13 认知综合之后、Gate-β 之前，执行自检缺口→补研→更新的循环。核心目标：确保研究深度和质量在交付前达到穷尽标准。

## 2. I01 执行步骤

### 2.1 步骤流程
1. **全量阅读**：阅读 NRSF-Full 中 §T03-§T13 的所有发现笔记
2. **缺口识别**：识别 6 类缺口（A-F）
3. **排级**：按严重程度排级（P0-P3）
4. **补研执行**：针对所有 P0 + P1 缺口 + Top-3 P2 缺口
5. **追加 NRSF**：补研结果以散文式笔记追加到 NRSF-Full
6. **重综合**：将补研发现融入 T13 综合叙事

### 2.2 缺口识别 6 类
| 类型 | 代码 | 描述 | 示例 |
|------|------|------|------|
| A 类 | 论证链不闭合 | 前提到结论之间存在逻辑跳跃 | "X 导致 Y"但缺少 X→Y 的因果机制 |
| B 类 | 缺少直接证据 | 论断仅基于间接推理，无一手数据/案例支撑 | 引用二手综述而非原始研究 |
| C 类 | 缺少反证/边界 | 核心论断无对立观点或适用边界说明 | "所有 X 都是 Y"但未讨论例外 |
| D 类 | 缺少具体案例 | 抽象论断无具体案例/数据支撑 | "趋势明显"但无数据点 |
| E 类 | 缺少跨媒介材料 | 仅有文字来源，缺少数据/图表/视频等 | 定量论断无数据可视化 |
| F 类 | 缺少利益相关者分析 | 未分析受影响各方立场 | 政策分析未考虑利益相关方 |

### 2.3 排级标准
| 级别 | 代码 | 描述 | 处理优先级 |
|------|------|------|-----------|
| P0 | 致命 | 核心论证链断裂，结论不可信 | 必须闭合 |
| P1 | 严重 | 重要论断缺少证据或反证 | 必须闭合或标注 |
| P2 | 重要 | 案例不足或跨媒介材料缺失 | Top-3 补研 |
| P3 | 改善 | 表述优化或细节补充 | 可选 |

### 2.4 补研执行规则
- 针对所有 P0 + P1 缺口 + Top-3 P2 缺口执行定向搜索
- 每轮补研最低搜索 5×3=15 次、最低来源 15 个、最低来源类型 3 种
- 补研搜索使用与 T05 相同的搜索策略（多引擎聚合 + 去重 + 来源标注）
- 补研结果以散文式笔记追加到 NRSF-Full §I01 下
- 更新 NRSF-Summary
- 更新 T13 综合叙事

### 2.5 执行规则
- 持续迭代直至所有 P0/P1 缺口闭合或标注为不可闭合
- 不设迭代上限，由质量驱动终止条件决定何时停止

## 3. I01 终止条件（YAML 协议版）

### 3.1 决策树
```yaml
i01_termination_check:
  conditions:
    - id: info_convergence
      condition: "ΔInfo(t) < ε（信息增益收敛）"
      action: terminate
      reason: "信息增益收敛，边际收益不足"

    - id: redundancy_detected
      condition: "补研发现与已有 NRSF 内容重叠度 ≥ 80%，连续 2 轮冗余"
      action: terminate
      reason: "信息冗余"

    - id: drift_detected
      condition: "补研方向与原始研究问题的语义距离 > 0.7"
      action: terminate
      reason: "研究方向漂移"

    - id: quality_achieved
      condition: "所有 P0/P1 缺口已闭合或标注为不可闭合"
      action: terminate
      reason: "质量达标"

    - id: continue_needed
      condition: "以上条件均不满足"
      action: continue
      reason: "仍有未闭合缺口"
```

### 3.2 终止条件评估顺序
1. 先检查 info_convergence（信息增益收敛，即 ΔInfo(t) < ε）
2. 再检查 redundancy_detected（效率判断）
3. 再检查 drift_detected（方向控制）
4. 再检查 quality_achieved（目标达成：所有 P0/P1 缺口已处理）
5. 以上均不满足则 continue_needed

## 4. 不可闭合缺口标注格式

```
**不可闭合缺口 #N**: {缺口描述} — 原因: {数据不可得|研究尚无定论|时效性无法满足|其他}
```

### 4.1 原因分类
- **数据不可得**：所需数据不存在或无法获取（如未公开的内部数据）
- **研究尚无定论**：学术界对该问题尚无共识（如前沿争议话题）
- **时效性无法满足**：需要长期跟踪才能得出结论（如政策长期影响）
- **其他**：上述分类无法涵盖的原因，需具体说明

### 4.2 标注规则
- 不可闭合缺口仍需记录在 NRSF 中
- 不可闭合缺口不阻塞 Gate-β 通过（P0/P1 必须闭合或标注）
- 不可闭合缺口在最终输出中以"研究局限"形式呈现

## 5. 研究问题重定向规则

### 5.1 规则
- 允许 ≤ 1 次研究问题重定向
- 重定向需用户确认
- 重定向后重新执行 T01→T00→T02 流程
- 已有 NRSF 内容保留，新方向研究追加到 NRSF

### 5.2 重定向触发条件
- I01 补研发现原始研究问题基于错误前提
- 语义距离 > 0.7 且无法通过调整回到原方向
- 用户主动要求调整研究方向

## 6. I01 与 NRSF 的交互规则

### 6.1 输入
- 全量加载 NRSF-Full（I01 是唯一需要全量加载的非 T20 任务）

### 6.2 输出
- 补研笔记追加到 NRSF-Full §I01（每轮一个子节 §I01-R{N}-{timestamp}）
- 更新 NRSF-Summary（核心论点、关键发现、未闭合论证链）
- 更新 T13 综合叙事（将补研发现融入）

### 6.3 双阶段输出格式
- **阶段 A**（结构化分析，用于 Gate-β 验证）：
  ```yaml
  i01_gap_analysis:
    round: {N}
    gaps_identified:
      - id: G01
        type: {A|B|C|D|E|F}
        severity: {P0|P1|P2|P3}
        description: "{缺口描述}"
        status: "{closed|unclosable|open}"
    gaps_closed_this_round: {N}
    gaps_remaining: {N}
    new_word_count: {N}
    search_count: {N}
  ```

- **阶段 B**（散文式 NRSF 笔记，供下游消费）：
  - 散文式补研笔记追加到 §I01
  - 每段 150-300 字，段落级引用
  - 包含补研发现、推理过程、与已有发现的关系

## 7. I01 Supervisor 检查项

I01 完成所有轮次后，I01_check.yml 检查以下必须通过项：
- 至少执行了 2 轮迭代
- 所有 P0 缺口已闭合或标注为不可闭合
- 所有 P1 缺口已闭合或标注为不可闭合
- 每轮补研结果已追加到 NRSF-Full
- NRSF-Summary 已更新
- T13 综合叙事已更新

## 8. 递归停止条件（M6）

满足以下任一条件即停止递归：

1. **解释力饱和**：继续追问不能提升对核心问题的解释力（新轮次未产生新根变量）
2. **根部触及**：已触及制度/历史/资源/利益/技术/组织层面的根部变量（无法再向上溯源）
3. **证据枯竭**：继续追问会进入无证据推测（证据等级跌破 C 级）
4. **主线偏离**：继续追问会偏离用户核心关切（漂移到次要议题）
5. **边界化**：该分支只适合放入边界/附录/反证部分，不适合作为主线继续展开

**铁律**：不得因为"已经列了很多模块"就停止深挖（这是伪停止）。递归的目标永远是找到根部变量，不是覆盖所有模块。

## 异常处理

异常处理遵循 `exhaust-retry-protocol.md` 的穷尽重试逻辑，不设穷尽重试替代或回退路径。

| 异常场景 | 处理策略 |
|---------|---------|
| 每轮迭代无实质性进展 | 检测连续2轮结论变化率<5%，穷尽尝试替代搜索策略和来源，持续迭代直至质量收敛，不设终止上限 |
| 深度信号持续触发但无法解决 | 穷尽尝试所有可用搜索路径和来源类型，标注"深度信号未解决"，输出当前最佳综合结论，建议人工介入 |
| 质量收敛 | 持续递归直至质量收敛，Token 不设上限 |
