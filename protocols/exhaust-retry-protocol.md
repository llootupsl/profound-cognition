# EXHAUST 穷尽重试协议 (EXHAUST Retry Protocol) v3.0

> 本协议是已删除的 `degradation-protocol.md` 的替代，遵循 EXHAUST 模式四大铁律。

---

## 一、协议声明

本协议为 profound-cognition 框架的核心重试协议，完全替代原 `degradation-protocol.md`。

**EXHAUST 模式四大铁律**：

1. **Token 不设上限** — 任何节点的执行不受 token 预算限制，持续输出直至质量达标
2. **时间不设限制** — 任何节点的执行不受时间预算限制，持续执行直至质量达标
3. **质量唯一优先** — 唯一的终止条件是质量达标，而非预算耗尽
4. **永远穷尽，无档位，无上限** — 不存在"低档位""高档位"之分，不存在任何形式的上限

任何与此协议矛盾的内容均应视为错误并修正。禁止引入任何形式的迭代上限、质量妥协策略、回退方案。

---

## 二、穷尽重试核心原则

| 原则 | 说明 |
|------|------|
| 节点失败时持续重试直至通过 | 任何节点在未通过 Supervisor 检查前，将持续重试，不存在"放弃"选项 |
| 外部工具不可用时穷尽尝试所有替代工具 | 按优先级链逐一尝试所有替代方案，最终回退至 LLM 内建能力 |
| 仅存在 QUALITY_MAINTAINED 状态 | 系统中所有输出必须达到完整质量标准，质量始终保持 |
| 不存在重试次数上限 | 重试次数无上限，直至通过为止 |
| 必须持续重试直至通过 | 这是 EXHAUST 模式的绝对红线，任何场景下均不可违反 |

---

## 三、节点状态枚举

系统中的节点仅存在以下四种状态：

| 状态 | 含义 | 替代说明 |
|------|------|----------|
| `completed` | 节点已通过 Supervisor 检查（PASS 或 PASS_WITH_WARNINGS） | — |
| `retrying` | 节点正在重试中 | **替代旧协议中已移除的质量妥协状态**。节点未通过检查，正在持续重试，所有节点必须持续重试直至通过，不存在"未达质量标准即标记完成"的路径 |
| `skipped` | 节点被跳过 | **仅限非关键路径节点**。关键路径节点不可跳过，必须持续重试直至 `completed` |
| `pending` | 节点尚未执行 | — |

**状态转换规则**：

```
pending → retrying → completed
pending → retrying → retrying → ... → completed   （无上限重试）
pending → skipped                                   （仅非关键路径）
retrying 不可转换为 skipped                          （关键路径永不放弃）
```

**注意**：系统仅存在 `QUALITY_MAINTAINED` 状态。原 `degradation-protocol.md` 中的质量妥协路径已被完全移除。

---

## 四、五种场景处理规则

### 场景一：Supervisor 判定 FAIL

当 Supervisor 对某节点的输出判定为 FAIL 时：

1. 系统将 **FAIL 原因** 和 **修正指令** 注入该节点的 context
2. 节点基于新的 context **重新执行**
3. 重新执行后再次提交 Supervisor 检查
4. **持续重试**直至 Supervisor 判定 `PASS` 或 `PASS_WITH_WARNINGS`
5. 不存在重试次数上限
6. 系统仅存在 QUALITY_MAINTAINED 状态

**操作流程**：

```
Supervisor 判定 FAIL
  → 提取 FAIL 原因
  → 生成修正指令
  → 注入修正指令到节点 context
  → 重新执行节点
  → 提交 Supervisor 检查
  → 若仍 FAIL，回到第一步
  → 若 PASS 或 PASS_WITH_WARNINGS，标记为 completed
```

**禁止行为**：
- 禁止在 N 次重试后放弃质量标准
- 禁止跳过该节点
- 禁止降低输出质量标准

---

### 场景二：外部工具不可用

当某个外部工具不可用时：

1. **穷尽尝试所有替代工具**（按优先级链逐一尝试，详见第五节）
2. 每个替代工具尝试失败后，记录失败原因，继续尝试下一个
3. 所有替代工具均不可用时，**使用 LLM 内建能力完成等效分析**
4. 使用 LLM 内建能力完成的分析必须标注 `[INTERNAL_REASONING]` 标签
5. 必须保持完整质量输出，不存在"简化输出"的选项
6. 不存在"回退为纯文本"的选项

**操作流程**：

```
工具 A 不可用
  → 记录失败原因
  → 尝试替代工具 B
  → 若 B 不可用，记录失败原因，尝试替代工具 C
  → ... 持续穷尽所有替代工具
  → 所有替代工具均不可用
  → 使用 LLM 内建能力完成等效分析
  → 标注 [INTERNAL_REASONING]
  → 提交 Supervisor 检查
```

**禁止行为**：
- 禁止因工具不可用而降低输出质量
- 禁止跳过需要该工具的分析步骤
- 禁止输出"由于工具不可用，以下分析已简化"等质量妥协声明

---

### 场景三：I01 迭代深化

在 I01 迭代深化过程中：

1. **持续迭代**直至所有 P0/P1 缺口闭合或标注为不可闭合
2. 不存在迭代上限
3. 终止条件**仅为**以下两种之一：
   - **ΔInfo(t) < ε**：信息增益收敛，继续迭代已无法产生有意义的增量
   - **所有缺口已处理**：P0/P1 缺口全部闭合或已标注为不可闭合并附理由
4. 不存在迭代次数守卫参数

**操作流程**：

```
执行一轮迭代深化
  → 计算信息增益 ΔInfo(t)
  → 若 ΔInfo(t) < ε，终止迭代
  → 若仍有未闭合的 P0/P1 缺口，继续迭代
  → 若所有缺口已处理，终止迭代
  → 否则，继续迭代（无上限）
```

**禁止行为**：
- 禁止设置迭代上限
- 禁止引入迭代次数守卫参数
- 禁止在 N 轮后放弃未闭合缺口的质量标准

---

### 场景四：Gate 门控 FAIL

当 Gate 门控检查判定 FAIL 时：

1. **退回重试**，持续直至通过
2. 不存在"最多退回 N 层"的限制
3. Gate-α 和 Gate-δ 均**无退回层数上限**

**操作流程**：

```
Gate 检查 FAIL
  → 退回至对应节点
  → 注入 FAIL 原因和修正指令
  → 重新执行该节点及其下游节点
  → 再次提交 Gate 检查
  → 若仍 FAIL，继续退回重试（无层数上限）
  → 若 PASS，继续执行
```

**禁止行为**：
- 禁止设置退回层数上限
- 禁止在退回 N 层后放弃质量标准
- 禁止跳过 Gate 检查

---

### 场景五：Phase 迭代

当 Phase 完成后仍有节点未通过时：

1. **持续迭代**，直至全部节点 PASS 或 PASS_WITH_WARNINGS
2. 不存在迭代上限
3. 不存在"3 轮后放弃质量标准"的逻辑

**操作流程**：

```
Phase 执行完成
  → 检查所有节点状态
  → 若存在 retrying 状态的节点，继续迭代
  → 对 retrying 节点注入修正指令，重新执行
  → 再次检查所有节点状态
  → 若全部 completed，Phase 完成
  → 否则，继续迭代（无上限）
```

**禁止行为**：
- 禁止设置 Phase 迭代上限
- 禁止在 N 轮后放弃未通过节点的质量标准
- 禁止跳过未通过节点

## 六、Supervisor 判定标准

### 6.1 三级判定体系

| 判定 | 含义 | 后续动作 |
|------|------|----------|
| `PASS` | 节点输出完全符合质量标准 | 标记为 `completed` |
| `PASS_WITH_WARNINGS` | 节点输出基本符合质量标准，存在可接受的微小瑕疵 | 标记为 `completed`，记录 warnings |
| `RETRYING` | 节点正在持续重试中 | 注入修正指令，重新执行 |

### 6.2 判定路径

```
Supervisor 检查节点输出
  → PASS → 标记 completed
  → PASS_WITH_WARNINGS → 标记 completed，记录 warnings
  → FAIL → 注入修正指令 → 重新执行 → 再次检查（循环）
```

**关键约束**：
- 不存在 `FAIL + 质量妥协` 的判定路径
- FAIL 后的唯一路径是重试，不存在质量妥协路径
- PASS_WITH_WARNINGS 中的 warnings 不影响节点完成状态

### 6.3 Supervisor 检查维度

Supervisor 在判定时需检查以下维度：

1. **完整性**：输出是否覆盖了所有要求的方面
2. **准确性**：输出中的事实、数据、推理是否准确
3. **深度**：分析是否足够深入，是否触及根本原因
4. **一致性**：输出是否与上下文其他部分一致
5. **可操作性**：输出是否提供了可执行的建议或结论

## 七、EXHAUST 一致性保证

### 7.1 一致性声明

本协议与 EXHAUST 模式四大铁律完全一致：

| 铁律 | 协议体现 |
|------|----------|
| Token 不设上限 | 重试次数无上限，每次重试的输出不受 token 预算限制 |
| 时间不设限制 | 重试持续时间无上限，不存在超时终止 |
| 质量唯一优先 | 终止条件仅为质量达标（PASS/PASS_WITH_WARNINGS），而非预算耗尽 |
| 永远穷尽，无档位，无上限 | 不存在质量妥协、简化、跳过等任何形式的"非穷尽"路径 |

### 7.2 矛盾处理规则

任何与此协议矛盾的内容均应视为错误并修正。具体包括：

- 若其他协议文件中存在迭代上限 → 视为错误，删除上限
- 若其他协议文件中存在质量妥协状态 → 视为错误，替换为 retrying
- 若其他协议文件中存在质量妥协策略 → 视为错误，删除该策略
- 若其他协议文件中存在回退方案 → 视为错误，删除回退方案
- 若其他协议文件中存在迭代次数守卫参数 → 视为错误，删除该参数

### 7.3 绝对禁止清单

以下行为在本协议下被绝对禁止，任何场景下均不可违反：

1. ❌ 设置重试次数上限
2. ❌ 引入质量妥协状态
3. ❌ 实施质量妥协策略
4. ❌ 跳过关键路径节点
5. ❌ 因预算耗尽而终止重试
6. ❌ 因工具不可用而降低输出质量
7. ❌ 引入迭代次数守卫参数
8. ❌ 设置 Gate 退回层数上限
9. ❌ 在 Phase 迭代中放弃质量标准
10. ❌ 任何形式的"放弃重试"行为

## 测试用例 (D3.4.4)

### 测试用例 1：穷尽重试触发

**给定输入**：节点 T05 第一次执行 self_check_score=60（< 85），触发重试。

**应产出**：节点状态变为 RETRYING，retry_feedback 注入 context_package，重试次数 +1。

### 测试用例 2：连续 3 次重试未通过

**给定输入**：节点 T05 连续 3 次重试，self_check_score 分别为 60/65/70（均 < 85）。

**应产出**：触发升级处理，调用更强模型或人工介入，标注"3 次重试未通过"。

### 测试用例 3：穷尽重试替代路径

**给定输入**：DoWhy 因果推断不可用（库未安装）。

**应产出**：按 L1→L2→L3→L4 逐级穷尽重试：L1 完整 DoWhy → L2 手动后门准则 → L3 因果图+识别策略声明 → L4 纯文字因果结构分析。最终执行 L4，标注"穷尽重试 L4"。

### 测试用例 4：重试成功

**给定输入**：节点 T05 第一次失败（score=70），第二次重试改进了证据覆盖度，score=88。

**应产出**：节点状态变为 completed，retry_count=1，记录"重试改进点：补充了 2 个 L1 来源"。
