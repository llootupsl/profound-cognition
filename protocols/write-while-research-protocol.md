# T20 写作中补研协议

## 1. 概述

**方法论原理**：边写边研协议基于"写作即思考"的认知假设：写作不是研究的后续步骤，而是研究过程的有机组成部分。通过边写边研，研究者能够在写作中发现知识缺口、触发新的研究问题，形成研究-写作的正反馈循环。

T20 从"纯渲染"改造为"渲染 + 按需补研"的交替过程。每章渲染后自检，发现缺口立即定向搜索补研。核心原则：补研不是重写，只修补需要的部分。

## 2. T20 执行流程

### 2.1 完整流程
1. 读取 NRSF-Full（全量或上下文自适应策略）+ output-expansion-protocol.md + typography-guide.md
2. 写标题 + 导言 → 图需求诊断 → 直接生成所需 Mermaid/SVG 图（自足）
3. 逐章渲染：从 NRSF 对应 § 节提取研究 → 按展开密度规则展开 → 图生成 → 本章自检
4. 本章自检通过 → 继续；不通过 → 执行补研 → 追加 NRSF §T20 → 更新本章 → 重新自检
5. 全文修订：统一风格 + 引用一致性 + NRSF↔输出一致性验证 + 生成附录
6. 输出最终成品

### 2.2 逐章渲染详细步骤
1. 从 NRSF 对应 § 节提取研究内容
2. 按章节展开密度规则展开（见 output-expansion-protocol.md）
3. 触发 内联 Mermaid/SVG 图生成 生成框架图/架构图（如需要）
4. 执行本章自检（见 §3）
5. 自检通过 → 继续下一章
6. 自检不通过 → 执行补研（见 §5）→ 追加到 NRSF §T20 → 更新本章 → 重新自检

## 3. 每章自检清单

### 3.1 强制项（必须通过）
| 序号 | 检查项 | 通过条件 |
|------|--------|---------|
| 1 | 本章字数 | ≥ 3000（§-级大章按 SKILL.md §0.1 各部分地板，合计 ≥100000） |
| 2 | 本章引用数 | ≥ 本章字数 / 1000 × 5 |
| 3 | 核心论断 NRSF 来源 | 本章所有核心论断在 NRSF 中有对应来源 |
| 4 | 推理链完整性 | 本章核心论点有完整的从前提到结论的推理链 |
| 5 | 反证/边界段落 | 本章至少包含 1 个反证或边界说明段落 |
| 6 | 链条展开 | 本章至少展开了 1 条链条（历史链/因果链/机制链等）≥ 3 节点 |

### 3.2 条件项（如适用）
| 序号 | 检查项 | 适用条件 | 通过条件 |
|------|--------|---------|---------|
| 7 | 图完整性 | 本章含图 | 图已生成 + caption 已写 + legend 已写 + 图与文字内容一致 |
| 8 | 跨媒介材料 | 研究涉及多媒介 | 至少引用了 1 个跨媒介材料并标注材料角色 |
| 9 | 利益相关者分析 | 研究涉及政策/商业 | 包含至少 1 个利益相关者分析段落 |

### 3.3 自检执行方式
- 每章渲染完成后立即执行自检
- 自检结果记录在 NRSF §T20 下
- 自检不通过时触发补研流程

## 4. 全局自检清单

### 4.1 检查项
| 序号 | 检查项 | 通过条件 |
|------|--------|---------|
| 1 | 总字数 | ≥ 100000（research_report；各部分字数地板见 SKILL.md §0.1 / output-expansion-protocol §2.4） |
| 2 | 总引用数 | ≥ 100 |
| 3 | 反证比率 | 反证段落 / 总论断段落 ≥ 0.25 |
| 4 | 来源域名 | ≥ 15 个不同域名 |
| 5 | 案例密度 | 每章至少 1 个案例 |
| 6 | 反证覆盖 | 至少 3 章包含反证段落 |
| 7 | 图完整性 | 所有图均有 caption + legend |
| 8 | 留白标记 | 无 []、TODO、待补充等留白标记 |

### 4.2 全局自检执行时机
- 所有章节渲染完成后执行
- 全局自检不通过时，针对失败项执行定向补研

## 5. 补研约束

### 5.1 核心约束
- 补研不是"重写全章"，只修补需要的部分
- 每次补研结果追加到 NRSF-Full §T20 下
- 每章补研次数不设上限，质量驱动终止
- 补研搜索使用与 T05 相同的搜索策略（多引擎聚合 + 去重 + 来源标注）
- 补研只搜索，不重新执行 T06-T13 的推理流程

### 5.2 搜索量化标准
- 每次补研最低搜索 2×2=4 次
- 每次补研最低来源 4 个
- 每次补研最低来源类型 1 种

### 5.3 补研结果处理
- 补研发现追加到 NRSF-Full §T20
- 更新 NRSF-Summary
- 更新当前章节内容
- 不影响其他已完成章节

## 6. 自检失败恢复流程

### 6.1 恢复流程
```
第 1 轮补研
  → 针对失败项定向搜索补研
  → 更新本章（新增不超过原字数 30%）
  → 重新自检
  → 通过 → 继续
  → 不通过 ↓

第 2 轮补研
  → 二次定向搜索补研
  → 更新本章（新增不超过原字数 20%）
  → 重新自检
  → 通过 → 继续
  → 不通过 ↓

超过 2 轮
  → 持续扩写直至章节字数达标，不设轮次上限
  → 在 NRSF §T20 中记录
  → 继续下一章
```

### 6.2 字数增长限制
- 第 1 轮补研：新增不超过原字数 30%
- 第 2 轮补研：新增不超过原字数 20%
- 超过 2 轮：持续扩写直至章节字数达标，不设轮次上限

## 7. NRSF 全量加载指令

### 7.1 加载方式
- 默认：全量加载 NRSF-Full
- 上下文窗口不足时：按上下文自适应策略加载（见 nrsf-protocol.md NRSF 分层摘要机制章节）
- T20 按章节分批加载时：先加载 NRSF-Summary + 当前章节对应 § 节 + 前后各 1 章 § 节

### 7.2 NRSF-输出一致性验证
- 全局自检阶段执行
- 方法：随机抽取输出中 10 个核心论断，验证是否在 NRSF 中有对应记录
- 通过率 ≥ 0.7 为合格
- 不合格时穷尽尝试回到对应章节重新渲染

## 异常处理与穷尽重试

| 异常场景 | 处理策略 |
|---------|---------|
| 研究与写作节奏不同步 | 优先保证研究完整性，写作可延后，标注"写作延迟" |
| 写作过程中发现研究缺口 | 暂停写作，穷尽尝试回到研究阶段补充，标注"研究缺口穷尽尝试" |
| 并行写作导致内容重复 | 合并重复内容，保留更完整的版本 |
| 写作质量不达标 | 标注"写作质量待提升"，在T19自评阶段重点检查 |
