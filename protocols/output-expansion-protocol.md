# 输出扩展协议 (Output Expansion Protocol)

> **状态**: 正式发布 (v3.0)
> **适用范围**: Profound Cognition — T20 渲染阶段
> **最后更新**: 2026-05-30

> **职责边界声明（D3.4.1）**：本协议负责**最终输出的内容密度与长度展开规则**——定义字数地板、章节展开密度、多源内容编织、信息密度公式、灌水警告机制。本协议**不定义**研究状态的存储格式或叙事引用机制（那是 `nrsf-protocol.md` 的职责），也不定义格式转换或内部标记净化（那是 `output-rendering-protocol.md` 的职责）。两者在 T20 渲染节点交汇但职责正交：NRSF 提供"读什么"，本协议提供"怎么展开"。详见 `docs/protocol-dependency-graph.md` §4.1。

---

## 1. 协议概述

### 1.1 目的

OutputExpansionProtocol 定义了将研究产物扩展为足够深度和长度的最终成品所需的内容密度标准。本协议确保输出不会因为缺少展开规则而被压缩到低于用户预期的长度。它与 [output-rendering-protocol.md](./output-rendering-protocol.md) 配合工作：前者负责格式和净化，本协议负责内容密度和长度。

### 1.2 核心原则

- **深度来自展开，而非灌水**：每增加一段内容都必须增加新的解释力、新证据、新案例、新反证或新边界
- **长度由密度保证，密度由规则保证**：不是喊"写长一点"，而是给出每章的展开下限
- **字数权限分离**：单轮输出长度 ≠ 分批章节长度 ≠ 最终成品长度 ≠ 平台传播长度
- **穷尽模式统一标准**：所有任务统一适用穷尽展开标准，由研究自然展开决定最终长度，不设人为上限

## 2. 穷尽模式统一标准

### 2.1 统一输出标准

本协议采用穷尽模式，所有任务统一适用以下标准：

| 维度 | 标准 |
|------|------|
| **最终成品字数** | ≥100000 字，由研究自然展开决定，不设上限 |
| **单轮输出** | 不设上限，按章节完整性截断 |
| **分批触发** | > 50000 字时分批交付，每批至少 1 个完整章节 |
| **wechat_article** | 字数由研究自然展开决定，排版层由 内置公众号排版系统 自动适配公众号格式 |

### 2.2 字数权限分离

必须区分四种长度：

1. **单轮输出长度**：当前一次回复最多写多少（受平台限制，但不对最终成品设限）
2. **分批章节长度**：这一批完成多少正文
3. **最终成品长度**：完整文章、报告或脚本最终需要多长
4. **平台传播建议长度**：为了发布、转发或平台阅读体验而建议的压缩长度

**铁律**：不得把单轮输出限制误认为最终成品长度。不得为了适配某个平台想象中的常规长度而牺牲主线完整性。

如果最终文章太长，可以另做：完整深度版、公众号发布版、精简传播版、短视频口播版、长图提纲版。压缩必须经过用户确认。

### 2.3 Token 预算估算规则

| 研究规模 | 预估字数 | Token 预算 | LLM 调用次数 |
|---------|---------|-----------|-------------|
| 标准研究 | 20000—40000 字 | 1M—2.5M | 25—40 次 |
| 深度研究 | 40000—60000 字 | 2.5M—4M | 40—55 次 |
| 正式智库级交付 | 60000—80000 字 | 3M—5M | 50—70 次 |
| **穷尽级交付（research_report 默认）** | **≥100000 字** | 5M—8M | 70—110 次 |

> research_report 默认走「穷尽级交付」行：≥10 万字、约 5M—8M Token、70—110 次调用。Token 预算为估算值，实际消耗取决于研究复杂度和补研轮次。**字数由各部分地板（见 SKILL.md §0.1）累计保证，不设上限。**

## 3. 章节展开密度协议

### 3.1 每章最低展开密度

每个核心章节至少包含：

| 内容元素 | 最低数量 |
|---------|---------|
| 核心判断 | 1 个 |
| 子判断 | 3—5 个 |
| 案例或材料 | 2—4 个 |
| 反证或边界 | 2—3 个 |
| 小结 | 1 个 |
| 与下一章过渡 | 1 个 |
| 历史链（≥ 3 节点） | 1 条 |
| 机制链（≥ 3 节点） | 1 条 |
| 利益相关者分析 | 1 个 |
| 可视化建议 | 1 个 |

### 3.2 八类链条展开规则

必须展开以下八类链条，每链至少 3 个节点：

1. **历史链**：起源 → 关键节点 → 当前状态 → 未来趋势
2. **因果链**：表层现象 → 直接原因 → 结构条件 → 根部变量
3. **机制链**：输入 → 处理 → 输出 → 反馈回路
4. **利益链**：谁获利 → 谁承担成本 → 谁有话语权 → 谁被忽略
5. **叙事链**：主流叙事 → 被遮蔽的叙事 → 反叙事 → 综合判断
6. **二阶反应链**：第一反应 → 适应/绕行 → 新均衡/新问题
7. **行动含义链**：防守型 → 适应型 → 进攻型
8. **图文表达链**：哪个判断适合什么图 → 图怎么服务论点

### 3.3 扩写禁止事项

不得通过以下方式扩写：
1. **不得复述前文**——新段落不得用不同措辞重复前面已陈述的观点或结论
2. **不得堆砌同义词**——不得通过同义替换方式对同一概念反复展开（如"结构性矛盾→体制性困境→制度性障碍"）
3. **不得填充常识**——不得用读者已知的常识性背景填充字数（如"随着互联网的发展..."类陈述）
4. **不得重复相同结论**——不得在同一篇输出中多次以不同形式重申同一结论
5. **不得用不同案例讲同一道理**——若两个案例说明的是同一个论点且无新增分析维度，只保留一个
6. **不得用"进一步/更深入/值得注意"开头**——此类过渡词暗示即将复述前文或做无实质扩写
7. **不得无证据扩写**——任何扩展性陈述必须有对应证据、案例、数据或逻辑推导支撑
8. **不得无结构地列举**——禁止"A、B、C、D..."式无分析、无层次、无优先级的平铺列举

### 3.4 扩写质量检查

每增加一段内容，都必须能回答：
> 这一段是否增加了新的解释力、新证据、新案例、新反证、新边界、新行动含义或新的可视化理解？

如果不能 → 删除或压缩。

### 3.5 单段自检（M14）

每扩写一段，执行七项闸门检查：

- [ ] 新解释力（对核心问题的因果解释更深入）
- [ ] 新证据（引用了之前未出现的数据/案例/研究）
- [ ] 新案例（展示了新的实例佐证）
- [ ] 新反证（讨论了之前未处理的反面论据）
- [ ] 新边界（明确了结论的适用范围和条件）
- [ ] 新行动含义（将洞察翻译为可操作的行动方向）
- [ ] 新可视化理解（提供了新的认知框架/类比/图示）

**七项全否**：删除或压缩该段为一句过渡。

### 3.6 扩写禁止事项（补充）

以下为 M14 配套的 8 条扩写禁止事项（与 T20a/T20b/T20c 渲染节点保持一致）：

1. **不得复述前文**——新段落不得用不同措辞重复前面已陈述的观点或结论
2. **不得堆砌同义词**——不得通过同义替换方式对同一概念反复展开
3. **不得填充常识**——不得用读者已知的常识性背景填充字数
4. **不得重复相同结论**——不得在同一篇输出中多次以不同形式重申同一结论
5. **不得用不同案例讲同一道理**——若两个案例说明的是同一个论点且无新增分析维度，只保留一个
6. **不得用"进一步/更深入/值得注意"开头**——此类过渡词暗示即将复述前文或做无实质扩写
7. **不得无证据扩写**——任何扩展性陈述必须有对应证据、案例、数据或逻辑推导支撑
8. **不得无结构地列举**——禁止"A、B、C、D..."式无分析、无层次、无优先级的平铺列举

## 4. 多源内容编织协议

### 4.1 编织元素清单

正式长文应至少编织以下元素：

1. 核心论点
2. 递归深挖链
3. 证据材料
4. 现实案例
5. 历史案例
6. 跨媒介文化材料
7. 反证
8. 二阶反应
9. 行动含义（仅用户要求建议时）
10. 配图与可视化说明

### 4.2 推荐编织路径

> 场景/故事引入 → 表层问题 → 反常识转折 → 机制拆解 → 证据支撑 → 跨媒介类比 → 反证边界 → 二阶反应 → 行动含义 → 图文总结

### 4.3 材料放置原则

| 材料类型 | 最适合放置位置 | 作用 |
|---------|--------------|------|
| 数据/官方资料 | 核心论证处 | 支撑事实判断 |
| 访谈/新闻案例 | 机制说明处 | 增强现实感 |
| 书籍/理论 | 深层解释处 | 提供思想框架 |
| 影视/歌曲/小说 | 开头、转折、文化解释处 | 呈现时代情绪 |
| 评论/论坛 | 舆论分析处 | 呈现公众认知样本 |
| 图表/图谱 | 复杂结构之后 | 帮助理解和传播 |
| 反证 | 每个核心判断之后 | 防止过度表达 |
| 行动含义 | 结尾或专章 | 转化为现实选择 |

## 5. 自然长文写作协议

### 5.1 正文写作基本规则

1. 正文以自然段为主，表格为辅
2. 表格用于研究过程、附录、对比、证据库，不得替代核心解释
3. 不得频繁使用"首先、其次、再次、最后"造成流水账
4. 不得一段一句判断，导致节奏过碎
5. 不得把协议语言直接搬进正文
6. 不得让读者感觉模型在填表
7. 可以使用场景化开头、微叙事、对比句、递进句、转折句、提问句
8. 可以使用文学、影视、歌曲、互联网案例作为引入或类比，但必须标注其材料角色
9. 自然不等于口水，不能牺牲事实边界和逻辑密度

### 5.2 每章自然推进结构

每个正式章节建议包含：

1. 引入问题
2. 表层看法
3. 为什么表层看法不够
4. 深层机制
5. 案例或材料支撑
6. 反证或边界
7. 小结并过渡到下一层

### 5.3 避免 AI 味

必须避免：

- "在当今社会……"
- "随着时代的发展……"
- "这是一个复杂的问题……"
- "我们需要辩证看待……"
- "总而言之……"
- "不可否认的是……"
- "它既有机遇也有挑战……"
- "这给我们带来了深刻启示……"
- 无证据的宏大总结
- 过度整齐的段落节奏
- 每段都以结论句开头
- 每章都用同一种结构

### 5.4 允许的自然表达方式

鼓励使用：

- 一个具体场景开头
- 一个反常识问题开头
- 一个被误解的常识开头
- 一个小人物处境开头
- 一个历史瞬间开头
- 一个流行文化镜像开头
- 一个数据或事件开头
- 一个概念冲突开头

所有表达都必须回到主线。

## 6. 分批交付增强协议

### 6.1 分批触发阈值

| 条件 | 规则 |
|------|------|
| ≤ 50000 字 | 不触发分批，单次交付 |
| > 50000 字 | 分批交付，每批至少 1 个完整章节 |

### 6.2 分批执行规则

1. 第一批优先完成研究方案、主线裁决、证据需求、递归剪枝和图文方案
2. 若用户明确要求"直接进入正文"，第一批不得默认输出完整研究方案
3. 每批开始前复述当前主线、上一批结论和本批目标
4. 每批结束后做主线漂移检测
5. 每批必须以完整章节结束，禁止在章节中途截断
6. 最后一批做总修订、自然文风统一、图文一致性审查和交付形态转换
7. 每批结尾显式输出压缩版研究状态文件

### 6.3 章节完整性铁律

每批必须以完整的章节作为结束点，禁止在章节中途截断。如果当前章节内容超过单批容量，应先拆分为子章节，按子章节边界截断。

## 7. T20 输出长度配置

### 7.1 渲染参数配置

T20 渲染阶段统一读取以下长度配置：

```yaml
output_length_config:
  unified:
    target_words: {min: 20000, max: null}
    min_chapters: 5
    expansion_protocol: "full"
    batch_enabled: true
    batch_threshold: 50000
    appendices_required: true
```

> `max: null` 表示不设上限，由研究自然展开决定。

### 7.2 成品类型配置

| 成品类型 | 说明 |
|---------|------|
| research_report | 深度研究报告，统一适用穷尽展开标准 |
| wechat_article | 字数由研究自然展开决定，排版层由 内置公众号排版系统 自动适配公众号格式 |
| course_material | 课程材料，统一适用穷尽展开标准 |

### 7.3 wechat_article 长度策略

wechat_article 不适用本协议的完整展开规则（受平台阅读体验约束），但仍遵循字数权限分离原则：

- 字数由研究自然展开决定，排版层由 内置公众号排版系统 自动适配公众号格式
- 不得因为"公众号文章"就默认压缩到 5000 字以下
- 若用户选择"深度版、超深度版、分批超长版"，wechat_article 可以超过 5000 字

## 9. T20 写作中补研集成

### 9.1 与 write-while-research-protocol.md 的关系

T20 从"纯渲染"改造为"渲染 + 按需补研"的交替过程。本协议的章节展开密度规则在 T20 执行时与 [write-while-research-protocol.md](./write-while-research-protocol.md) 联动：

- T20 逐章渲染时，按本协议 §3 的展开密度规则展开
- 每章自检不通过时，触发补研流程（见 write-while-research-protocol.md §5）
- 补研结果追加到 NRSF §T20，然后更新当前章节

### 9.2 补研对展开密度的影响

- 补研新增内容不计入原始展开密度计算
- 补研后重新自检时，以补研后的总内容重新评估展开密度
- 补研新增内容不超过原字数 30%（第 1 轮）或 20%（第 2 轮）

### 9.3 全局自检与展开密度

T20 全局自检阶段（见 write-while-research-protocol.md §4），需额外验证：
- 每章展开密度是否符合本协议 §3 的要求
- 不符合时触发定向补研（仅针对密度不足的章节）

## 10. 信息密度度量（R8-01）

> **目的**：通过量化指标衡量输出的信息密度，识别"灌水"章节，确保每一段内容都贡献实质性信息增量。本节定义信息密度的计算公式、独立论点数计算方法、密度分级标准、灌水警告机制及章节级分布报告。本节为 R8-01 信息密度度量的执行规范。

### 10.1 信息密度公式（3.7.2）

信息密度（Information Density, ID）衡量单位字数内的有效信息含量，计算公式如下：

```
ID = (独立论点数 × 证据数 × 反证数 × 跨维度连接数) / 字数 × 1000
```

**变量定义**：

| 变量 | 定义 | 计算方式 |
|------|------|---------|
| 独立论点数（N_args） | 语义去重后的独立论点数量 | 见 §10.3 |
| 证据数（N_evid） | 支撑论点的证据条目数 | 统计 `[来源:...]` 标记 + 数据/案例引用 |
| 反证数（N_counter） | 反证/对立证据条目数 | 统计反证段落及对立来源引用 |
| 跨维度连接数（N_cross） | 跨元维度（L1-L9 / 9-14 维度）的连接数 | 统计跨维度引用与映射关系 |
| 字数（W） | 该章节/全文的中文字符数 | 不含标点、空格、Markdown 标记 |

**计算示例**：

某章节 2000 字，含 8 个独立论点、15 条证据、3 条反证、5 个跨维度连接：

```
ID = (8 × 15 × 3 × 5) / 2000 × 1000 = 1800 / 2000 × 1000 = 900
```

> **注**：ID 值为无量纲数值，数值越高表示信息密度越大。本公式设计为乘积形式，确保任一维度缺失（如反证数为 0）将导致 ID 显著下降，从而强制要求四维度均衡。

### 10.2 信息密度计算伪代码（3.7.2 续）

```python
def compute_information_density(text: str) -> dict:
    """计算文本的信息密度。

    Args:
        text: 待评估的文本内容（章节级或全文级）

    Returns:
        dict: {
            "density": float,           # 信息密度值
            "n_args": int,              # 独立论点数
            "n_evid": int,              # 证据数
            "n_counter": int,           # 反证数
            "n_cross": int,             # 跨维度连接数
            "word_count": int,          # 字数（不含标点/空格/Markdown）
            "grade": str,               # 密度分级（见 §10.4）
            "warnings": list            # 灌水警告（见 §10.5）
        }
    """
    # Step 1: 字数统计（去除标点、空格、Markdown 标记）
    word_count = count_chinese_chars(
        text,
        exclude_punctuation=True,
        exclude_markdown=True,
        exclude_spaces=True
    )

    if word_count == 0:
        return {"density": 0.0, "grade": "EMPTY", "warnings": ["空章节"]}

    # Step 2: 提取并去重独立论点（见 §10.3）
    raw_args = extract_arguments(text)
    n_args = deduplicate_arguments(raw_args, similarity_threshold=0.8)

    # Step 3: 统计证据数
    n_evid = count_evidence(text)  # 正则匹配 [来源:...] + 数据引用 + 案例引用

    # Step 4: 统计反证数
    n_counter = count_counter_evidence(text)  # 反证段落 + 对立来源

    # Step 5: 统计跨维度连接数
    n_cross = count_cross_dimension_links(text)  # 跨 L1-L9 / 9-14 维度引用

    # Step 6: 计算信息密度
    # 注：任一维度为 0 时密度归零（乘积公式设计意图）
    if n_args == 0 or n_evid == 0 or n_counter == 0 or n_cross == 0:
        density = 0.0
    else:
        density = (n_args * n_evid * n_counter * n_cross) / word_count * 1000

    # Step 7: 密度分级（见 §10.4）
    grade = classify_density(density)

    # Step 8: 灌水警告（见 §10.5）
    warnings = generate_watering_warnings(
        density, grade, n_args, n_evid,
        n_counter, n_cross, word_count
    )

    return {
        "density": round(density, 2),
        "n_args": n_args,
        "n_evid": n_evid,
        "n_counter": n_counter,
        "n_cross": n_cross,
        "word_count": word_count,
        "grade": grade,
        "warnings": warnings
    }
```

### 10.3 独立论点数计算方法（3.7.3）

独立论点数（N_args）的计算采用**语义相似度去重**策略，避免同义论点被重复计数。

#### 10.3.1 计算流程

```
原始论点提取 → Embedding 向量化 → 余弦相似度矩阵 → 阈值去重（> 0.8）→ 独立论点计数
```

#### 10.3.2 实现伪代码

```python
import numpy as np

def deduplicate_arguments(raw_args: list, similarity_threshold: float = 0.8) -> int:
    """对原始论点列表进行语义去重，返回独立论点数。

    Args:
        raw_args: 从文本中提取的原始论点列表（字符串列表）
        similarity_threshold: 语义相似度阈值，超过此值的两个论点
                              视为同一论点（默认 0.8）

    Returns:
        int: 去重后的独立论点数
    """
    if not raw_args:
        return 0

    # Step 1: 使用 Qdrant 适配器生成 embedding
    # 适配器见 knowledge/external-capabilities/TC-102-Qdrant.md
    embeddings = []
    for arg in raw_args:
        emb = qdrant_adapter.embed(text=arg, model="bge-large-zh-v1.5")
        embeddings.append(emb)

    embeddings_matrix = np.array(embeddings)  # shape: (n_args, dim)

    # Step 2: 计算余弦相似度矩阵
    # 归一化后点积即为余弦相似度
    norms = np.linalg.norm(embeddings_matrix, axis=1, keepdims=True)
    norms = np.where(norms == 0, 1, norms)  # 防止除零
    normalized = embeddings_matrix / norms
    similarity_matrix = normalized @ normalized.T  # shape: (n_args, n_args)

    # Step 3: 贪心聚类去重
    # 若两个论点相似度 > threshold，归为同一簇
    visited = set()
    independent_count = 0

    for i in range(len(raw_args)):
        if i in visited:
            continue
        independent_count += 1
        visited.add(i)
        for j in range(i + 1, len(raw_args)):
            if j not in visited and similarity_matrix[i, j] > similarity_threshold:
                visited.add(j)

    return independent_count
```

#### 10.3.3 论点提取规则

从文本中提取论点的规则：

1. **显式论点**：以"我们认为"、"本研究发现"、"核心判断是"、"结论是"等引导的句子
2. **隐式论点**：段落首句的判断性陈述（含"是"、"会"、"导致"、"使得"等判断动词）
3. **子论点**：以"其一"、"其二"、"首先"、"其次"等引导的子判断
4. **排除项**：纯描述性陈述、引用他人观点（标注为证据而非论点）、过渡句

#### 10.3.4 Qdrant 适配器集成

本计算依赖 Qdrant 向量数据库适配器（能力卡：`knowledge/external-capabilities/TC-102-Qdrant.md`）：

- **Embedding 模型**：`bge-large-zh-v1.5`（中文优化，1024 维）
- **相似度度量**：余弦相似度（Cosine Distance）
- **去重阈值**：0.8（可配置，默认值）
- **回退策略**：若 Qdrant 不可用，回退到 Jaccard 相似度（基于词集合，阈值 0.6）

### 10.4 信息密度分级（3.7.4）

根据 ID 值将信息密度分为三级：

| 分级 | ID 值范围 | 含义 | 适用场景 | 处置规则 |
|------|----------|------|---------|---------|
| **高密度（学术级）** | ID ≥ 6.0 | 单位字数内信息含量极高，论点密集、证据充分、反证到位、跨维度连接丰富 | 学术论文、智库级研究报告 | 直接通过，标记为优质章节 |
| **中密度（专业级）** | 4.0 ≤ ID < 6.0 | 信息密度达标，但仍有提升空间 | 专业报告、行业分析 | 通过，但建议补充反证或跨维度连接以提升至高密度 |
| **低密度（灌水风险）** | ID < 4.0 | 单位字数内信息含量不足，可能存在灌水、复述、堆砌 | — | 触发灌水警告（见 §10.5），要求定向补研或压缩 |

#### 10.4.1 分级判定伪代码

```python
def classify_density(density: float) -> str:
    """根据信息密度值判定分级。"""
    if density >= 6.0:
        return "HIGH"    # 高密度（学术级）
    elif density >= 4.0:
        return "MEDIUM"  # 中密度（专业级）
    else:
        return "LOW"     # 低密度（灌水风险）
```

#### 10.4.2 分级与 output_type 的关系

| output_type | 最低密度要求 | 说明 |
|-------------|-------------|------|
| research_report | ≥ 4.0（MEDIUM） | 学术级报告要求中密度以上，任一章节 < 4.0 触发补研 |
| wechat_article | ≥ 3.0 | 公众号文章允许较低密度（受阅读体验约束），但 < 3.0 仍触发警告 |
| course_material | ≥ 4.0（MEDIUM） | 课程材料要求中密度以上，确保教学信息含量 |

### 10.5 灌水警告机制（3.7.5）

当章节信息密度 < 4.0 时，触发灌水警告，标注低密度章节及原因。

#### 10.5.1 警告触发条件

```
IF chapter_density < 4.0:
    TRIGGER watering_warning
    IDENTIFY root_cause
    GENERATE remediation_suggestion
```

#### 10.5.2 灌水原因诊断

低密度章节的常见原因及诊断规则：

| 原因代码 | 原因描述 | 诊断条件 | 修复建议 |
|---------|---------|---------|---------|
| W-01 | 论点稀疏 | n_args < 3 或 n_args / word_count < 0.002 | 补充独立论点，每 500 字至少 1 个新论点 |
| W-02 | 证据不足 | n_evid < 5 或 n_evid / n_args < 2 | 每个论点至少补充 2 条独立证据 |
| W-03 | 反证缺失 | n_counter == 0 | 补充至少 1 条反证或对立观点 |
| W-04 | 跨维度连接缺失 | n_cross == 0 | 建立与其他维度（L1-L9 / 9-14）的映射关系 |
| W-05 | 字数虚高 | word_count > 3000 且 density < 2.0 | 压缩冗余表述，删除复述段落 |
| W-06 | 复述检测 | 语义去重后 n_args 下降率 > 50% | 删除同义重复论点，替换为新论点 |

## 11. Phase 3.5 分批交付规范（R2-04）

> **目的**：将 Phase 3.5（T20 渲染阶段）的输出分批次交付，确保超长输出（≥10 万字）在单轮输出受限时仍能完整交付，同时每批次都通过 Gate 检查保证质量。本节为 R2-04 分批交付规范的执行定义，是对 §6「分批交付增强协议」的 Phase 3.5 专项细化。

### 11.0 与 EXHAUST 模式「禁止缩减」原则的关系（R2-04 消除矛盾）

> **R2-04 关键声明**：分批交付是对**交付节奏**的工程性拆分，不构成对 EXHAUST 模式「禁止缩减」原则的违反。判定标准如下：

1. **分批 ≠ 缩减**：分批交付将完整成品按章节边界拆分为多个批次逐次交付，**所有章节内容仍按 §3 章节展开密度协议与 §10 信息密度度量完整展开**，仅是交付时间点拆分，不删除/压缩/简化任何章节内容
2. **硬门控保证深度**：每批次交付前必须通过 §11.4 规则 4 的硬门控检查（章节展开密度、信息密度、扩写禁止事项、单段自检、主线漂移检测、章节完整性），任一未达标即触发回退重渲染——这与 EXHAUST 禁止清单第 3 项「条件性质量降低」、第 13 项「节点内深度缩水」的执行口径完全一致
3. **断点续传保证完整性**：§11.5 规则 5 的断点续传机制确保所有批次最终全部交付，不存在"分批后剩余批次丢弃"的路径——这与 EXHAUST 禁止清单第 8 项「跳过关键路径节点」对齐（批次视为渲染节点的子任务，不可跳过）
4. **字数地板不受分批影响**：分批交付下，各章节字数地板（§2.4）与全文总字数地板（≥10 万字）保持不变，分批仅改变交付节奏，不改变字数下限
5. **与禁止清单的关系**：分批交付是交付机制的工程实现，不触及 EXHAUST 四大铁律（Token 不设上限、时间不设限制、质量唯一优先、永远穷尽无档位无上限）——分批不设批次数上限（由章节完整性自然决定），单批次内不设 token 上限，质量门控不妥协

### 11.1 规则 1：分批交付定义

分批交付指将 Phase 3.5（T20 渲染阶段）的最终输出按章节或章节组划分为多个批次，逐批交付。每个批次必须包含完整结构（引入、正文、小结），内容按研究主线递进，不得出现「半截章节」或「无小结的片段」。

- **批次完整性**：每批次是可独立阅读的完整单元，含本批次章节的引入、正文、小结
- **内容递进**：批次之间按研究主线递进，后一批次不重复前一批次已交付内容
- **结构一致**：每批次遵循 §3 章节展开密度协议

### 11.2 规则 2：触发条件

当 Phase 3.5 的预估输出字数超过以下阈值时，自动触发分批交付：

| 触发条件 | 阈值 | 处置 |
|---------|------|------|
| 预估总字数 > 50000 字 | 50000 | 自动分批 |
| 单轮输出受限（平台/Token 限制） | 单轮无法完成 | 强制分批 |
| 用户显式要求分批 | 用户指定 | 按用户要求分批 |

- 预估字数由 T00 大纲的章节字数地板累计估算
- 触发分批后，T20 渲染阶段按批次规划执行，不再尝试单轮全量输出
- 未达阈值时优先单轮交付，不强制分批

### 11.3 规则 3：批次大小

每批次建议字数范围：

| 维度 | 建议 | 说明 |
|------|------|------|
| 每批次字数下限 | 5000 字 | 低于此值批次过碎，增加追踪开销 |
| 每批次字数上限 | 10000 字 | 超过此值单轮输出风险高 |
| 每批次章节数 | 1-2 个完整章节 | 以章节完整性优先，字数其次 |

- 批次大小以「完整章节」为优先边界，字数为参考
- 若单个章节超过 10000 字，按子章节边界拆分批次
- 若单个章节不足 5000 字，可与相邻章节合并为一批

### 11.4 规则 4：硬门控规则

每批次交付前必须通过 Gate 检查，未通过则不得交付：

| 门控项 | 检查内容 | 处置 |
|--------|---------|------|
| 章节展开密度 | 符合 §3 章节展开密度协议 | 不达标 → 定向补研后重渲染 |
| 信息密度 | 符合 §10 信息密度度量（ID ≥ 4.0） | 不达标 → 触发灌水警告并补研 |
| 扩写禁止事项 | 符合 §3.3 / §3.6 扩写禁止事项 | 违反 → 删除违规内容后重渲染 |
| 单段自检（M14） | 符合 §3.5 七项闸门检查 | 不达标 → 压缩或补研 |
| 主线漂移检测 | 本批次未偏离研究主线 | 漂移 → 回退重渲染 |
| 章节完整性 | 以完整章节结束，无半截章节 | 不完整 → 延伸至章节边界 |

- 任一硬门控项未通过 → 批次不得交付，触发回退重渲染
- 硬门控检查结果记录到 `execution_ledger.batch_delivery.gate_check`
- 硬门控与 Gate-终（T28）的关系：批次硬门控是过程检查，Gate-终是终局检查，两者不互替

### 11.5 规则 5：中断恢复

支持批次级别的断点续传，确保中断后可从最近已交付批次恢复：

#### 断点续传机制

1. **批次状态持久化**：每批次交付后，将批次状态写入 `checkpoint.batch_delivery`
2. **状态字段**：含已交付批次列表、当前批次进度、待交付批次队列
3. **恢复流程**：中断恢复时，读取最近 checkpoint，跳过已交付批次，从下一批次继续
4. **部分批次处置**：若中断发生在批次交付中途，该批次标记为 INCOMPLETE，恢复时重新渲染该批次

#### Checkpoint 格式

```yaml
batch_delivery_checkpoint:
  delivery_id: "BD-2026-001"           # 交付唯一标识
  total_batches: 12                     # 总批次数
  delivered_batches:                    # 已交付批次
    - batch_id: "BD-2026-001-B01"
      chapters: ["§1"]
      word_count: 8500
      delivered_at: "2026-06-25T10:00:00"
      gate_check: "PASS"
    - batch_id: "BD-2026-001-B02"
      chapters: ["§2.1", "§2.2"]
      word_count: 9200
      delivered_at: "2026-06-25T10:30:00"
      gate_check: "PASS"
  current_batch:                        # 当前批次（中断时）
    batch_id: "BD-2026-001-B03"
    chapters: ["§2.3"]
    status: "INCOMPLETE"                # PENDING / IN_PROGRESS / INCOMPLETE / DONE
    rendered_words: 3200
    expected_words: 8000
  pending_batches:                      # 待交付批次
    - batch_id: "BD-2026-001-B04"
      chapters: ["§2.4", "§3.1"]
    - batch_id: "BD-2026-001-B05"
      chapters: ["§3.2"]
  resumed_from: "BD-2026-001-B03"       # 恢复起点
```

### 11.6 规则 6：批次标识

每批次分配唯一标识，便于追踪与审计：

#### 标识格式

```
BD-{delivery_id}-B{batch_sequence}

示例：BD-2026-001-B01
```

- `delivery_id`：本次 Phase 3.5 交付的唯一 ID（如 2026-001）
- `batch_sequence`：批次序号，两位数字（B01, B02, ...）

#### 标识使用规则

1. **批次头**：每批次输出开头标注批次标识、章范围、字数、批次序号/总批次数
2. **批次尾**：每批次输出结尾标注下一批次预告（章范围、预估字数）
3. **审计追踪**：批次标识写入 `execution_ledger.batch_delivery`，便于事后审计
4. **用户可见**：批次标识在交付时对用户可见，便于用户追踪交付进度

#### 批次头格式

```
【批次 BD-2026-001-B03 / 共 12 批】
章节范围：§2.3 经济维度
本批字数：8000 字
上一批次：BD-2026-001-B02（§2.1-§2.2，9200 字，PASS）
下一批次：BD-2026-001-B04（§2.4-§3.1，预估 9000 字）
---
```

#### 批次尾格式

```
---
【批次 BD-2026-001-B03 结束】
本批 Gate 检查：PASS（信息密度 5.8，展开密度达标）
下一批次预告：BD-2026-001-B04，§2.4-§3.1，预估 9000 字
```

## 异常处理与穷尽重试

| 异常场景 | 处理策略 |
|---------|---------|
| 扩展目标字数无法达到 | 持续扩展直至字数达标，不设时间/字数上限 |
| 扩展过程中引入幻觉内容 | 立即停止扩展，穷尽尝试回到扩展前版本，标注"幻觉检测触发" |
| 扩展导致逻辑链断裂 | 暂停扩展，修复断裂后再继续，标注"逻辑修复" |
| 字数未达标 | 持续扩展直至字数达标，不设时间/字数上限 |

## 测试用例 (D3.4.4)

### 测试用例 1：字数地板检查

**给定输入**：research_report 最终成品字数为 80000 字（< 100000 字地板）。

**应产出**：触发字数不足警告，标注"未达字数地板（80000/100000）"，要求补充展开。

### 测试用例 2：信息密度计算

**给定输入**：某章节 5000 字，包含 10 个独立论点、15 个证据、5 个反证、8 个跨维度连接。

**应产出**：信息密度 = (10×15×5×8)/5000×1000 = 1200/5000×1000 = 240... 实际公式 (10×15×5×8)/5000×1000 = 6000/5 = 1200。密度等级 ≥6.0 高密度。

### 测试用例 3：灌水警告

**给定输入**：某章节 3000 字，仅 2 个独立论点、3 个证据、0 个反证、1 个跨维度连接。

**应产出**：信息密度 = (2×3×0×1)/3000×1000 = 0（反证数为 0 导致密度为 0）。触发灌水警告，标注"低密度章节，缺少反证"。

### 测试用例 4：分批交付触发

**给定输入**：最终成品预估 60000 字（> 50000 字阈值）。

**应产出**：触发分批交付，每批至少 1 个完整章节，批次标识格式正确。
