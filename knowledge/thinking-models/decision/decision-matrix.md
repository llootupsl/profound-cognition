# 五维决策矩阵引擎 -- 决策分析的核心计算与评估中枢

> **模块标识**: `knowledge/thinking-models/decision/decision-matrix`
> > **职责**: 作为决策分析系统的核心引擎，接收经过分类的决策类问题，通过五维评估框架对决策选项进行量化评分，融合8项决策技术提供结构化分析，输出加权综合评分与决策建议报告
> **依赖**: `knowledge/thinking-models/decision/scenario-simulator`（场景推演与替代方案生成）、`knowledge/research-methods`（九层研究底座）、`knowledge/cognitive-framework`（认知流水线）
> **核心能力**: 8项决策分析技术（利弊分析器、风险评估器、机会成本计算器、决策树生成器、场景模拟器、价值观匹配器、长期影响分析器、替代方案生成器）

### 2.2 维度一：利弊分析（权重 0.25）

**核心思想**: 系统化地量化决策选项的全部收益与全部成本，计算净收益值。

#### 收益分类体系

```
收益结构
├── 直接收益 (DB)
│ ├── 财务收益: 可量化的金钱回报（月薪增长、投资回报等）
│ ├── 能力收益: 可验证的技能提升（证书、技术栈扩展等）
│ └── 资源收益: 可获取的人脉、平台、工具等资源
│
├── 间接收益 (IB)
│ ├── 品牌增值: 个人/组织影响力的提升
│ ├── 路径依赖: 为未来机会打开的新通道
│ └── 知识溢出: 对其他领域的正向迁移效应
│
└── 情感收益 (EB)
 ├── 成就感: 自我实现与满足程度
 ├── 安全感: 对未来的确定性与掌控感
 └── 幸福感: 日常生活质量的改善
```

#### 成本分类体系

```
成本结构
├── 直接成本 (DC)
│ ├── 财务支出: 需要支付的金钱（学费、投资本金等）
│ ├── 时间投入: 需要消耗的时间（学习周期、工作时长等）
│ └── 精力消耗: 需要付出的体力与脑力
│
├── 间接成本 (IC)
│ ├── 机会丧失: 因选择此方案而放弃的其他机会
│ ├── 关系损耗: 对现有社交关系的负面影响
│ └── 声誉风险: 失败可能带来的形象损害
│
└── 情感成本 (EC)
 ├── 焦虑感: 对不确定性的担忧程度
 ├── 压力感: 执行过程中的心理负担
 └── 遗憾感: 放弃其他选项的心理失落
```

#### 净收益计算公式

```
总收益 TR = 0.45×DB + 0.30×IB + 0.25×EB
总成本 TC = 0.45×DC + 0.30×IC + 0.25×EC
净收益 NB = TR - TC
利弊维度得分 = normalize(NB) → 映射至 [0, 100]
```

| 净收益水平 | 得分区间 | 评级 |
|-----------|---------|------|
| 极高净收益 | 85-100 | A+ |
| 高净收益 | 70-84 | A |
| 中等净收益 | 55-69 | B |
| 低净收益 | 40-54 | C |
| 负净收益 | 0-39 | D |

### 2.3 维度二：风险评估（权重 0.25）

**核心思想**: 量化识别决策中可能存在的风险，评估其发生概率与影响程度，并提供缓解策略。

#### 风险评估矩阵

```
风险分 R = P × I （取值范围: 1-25）
P = 发生概率 (1-5), I = 影响程度 (1-5)
```

| 风险等级 | 风险分 | 处理策略 |
|---------|--------|---------|
| 低风险 | 1-6 | 可接受，常规监控 |
| 中风险 | 7-12 | 需制定缓解计划 |
| 高风险 | 13-18 | 需专项应对措施 |
| 极高风险 | 19-25 | 建议重新评估或放弃 |

#### 风险评分公式

```
加权风险分 WRR = Σ(Ri × Wi) / Σ(Wi)
风险维度得分 = 100 - (WRR / 25) × 100
得分 = clamp(100 - WRR × 4, 0, 100)
```

#### 风险识别检查清单

对每个决策选项检查：财务风险、时间风险、能力风险、市场风险、关系风险、健康风险、合规风险、声誉风险。

---

### 2.4 维度三：成本分析（权重 0.20）

**核心思想**: 全面识别显性与隐性成本，避免因遗漏隐性成本而导致决策偏差。

#### 成本分析框架

```
总拥有成本 TCO = 直接成本 + 机会成本 + 隐性成本
机会成本 OC = max(放弃的各选项的预期收益)
成本效率比 CER = 预期总收益 / TCO
```

| 成本效率比 | 得分区间 |
|-----------|---------|
| CER >= 3.0 | 85-100 |
| CER 2.0~3.0 | 70-84 |
| CER 1.5~2.0 | 55-69 |
| CER 1.0~1.5 | 40-54 |
| CER < 1.0 | 0-39 |

#### 沉没成本识别规则

沉没成本不得纳入决策计算（理性决策原则）。但需识别"沉没成本谬误"风险——用户是否因已投入而拒绝放弃不利方案。

#### 隐性成本挖掘清单

学习曲线成本、转换成本、维护成本、协调成本、错误成本、情绪成本、信息不对称成本。

### 2.5 维度四：价值观匹配（权重 0.15）

**核心思想**: 评估决策选项与个人核心价值观的契合程度，确保决策符合长期人生方向。

#### 8个核心价值维度

| 编号 | 维度 | 核心内涵 |
|-----|------|---------|
| V1 | 成长发展 (G) | 持续学习与自我提升 |
| V2 | 自由自主 (A) | 独立决策与时间掌控 |
| V3 | 社会贡献 (S) | 对他人和社会的正面影响 |
| V4 | 创新创造 (I) | 创造新事物与解决新问题 |
| V5 | 安全稳定 (S) | 确定性与可预测性 |
| V6 | 家庭关系 (F) | 与家人的连接与陪伴 |
| V7 | 财富积累 (W) | 物质财富的增长与保障 |
| V8 | 健康福祉 (H) | 身心健康与生活质量 |

#### 适配度评分算法

```
步骤1: 用户对8个维度分别评分 (1-10)，反映重视程度
步骤2: 评估决策选项对8个维度的影响 (-5 到 +5)
步骤3: VAF = Σ(重视度 × max(正面影响, 0)) / Σ(重视度 × 5)
步骤4: 价值观维度得分 = VAF × 100
步骤5: 若任一核心维度(重视度>=7)的影响<=-3 → 触发"价值观冲突"一票否决预警
```

---

### 2.6 维度五：长期影响（权重 0.15）

**核心思想**: 评估决策在1年、3年、5年、10年四个时间维度上的累积影响。

#### 影响时间线权重

```
I(1年) 权重 = 0.20 | I(3年) 权重 = 0.25 | I(5年) 权重 = 0.30 | I(10年) 权重 = 0.25
```

#### 影响衰减模型

```
对于正面影响: I_pos(t) = I_0 × e^(-λ_pos × t) + I_base
对于负面影响: I_neg(t) = I_0 × e^(-λ_neg × t)
累积影响: CI(T) = ∫[0,T] (I_pos(t) - I_neg(t)) dt
长期影响维度得分: LI = 0.20×I(1) + 0.25×I(3) + 0.30×I(5) + 0.25×I(10)
```

#### 长期影响评估维度

职业发展、财务状况、人际关系、个人成长、生活质量。

## 三、综合评分算法

### 3.1 加权求和模型

```
综合得分 CS = 0.25×S1(利弊) + 0.25×S2(风险) + 0.20×S3(成本) + 0.15×S4(价值观) + 0.15×S5(长期影响)

综合评级:
90-100 → S+ 极优决策 | 80-89 → S 优秀决策 | 70-79 → A 良好决策
60-69 → B 中等决策 | 50-59 → C 一般决策 | 40-49 → D 较差决策 | 0-39 → F 极差决策
```

### 3.2 一票否决机制

当以下任一条件触发时，综合评级自动降为 F：

| 否决条件 | 触发条件 |
|---------|---------|
| V1 致命风险 | 任一风险分 R >= 20 且无有效缓解措施 |
| V2 核心价值观冲突 | 核心价值维度受到严重冲击(影响<=-3)且不可调和 |
| V3 成本不可承受 | TCO 超过用户可承受上限的150% |
| V4 长期影响严重负面 | 10年累积影响 CI(10) < -0.5 且不可逆转 |

### 3.3 多选项排序算法

1. 对每个选项独立计算五维得分
2. 计算综合得分并降序排列
3. 若相邻选项差距 < 5，标记为"高度接近，需结合场景分析"
4. 触发一票否决的选项移至末尾并标记

## 五、8项决策技术融合接口

| DEC-TECH-007 | 长期影响分析器 | 维度五 | 1/3/5/10年四节点影响评估 |


## 七、质量自检清单

### 数据完整性
- 决策选项数量 >= 2
- 每个选项五维得分全部在 [0,100]
- 权重和 Σ(Wi) = 1.00
- 每个选项至少3利3弊

## 八、决策矩阵决策规则（MC-147 Net-Benefit-Composite / MC-148 Risk-TCO）

| 条件 | 判定 | 行动 |
|------|------|------|
| 综合得分 CS ≥ 90 | 极优决策（S+） | 强烈推荐，可直接执行 |
| 综合得分 CS 70-89 | 优秀/良好决策（S/A） | 推荐，关注薄弱维度 |
| 综合得分 CS 50-69 | 中等/一般决策（B/C） | 需改进，关注低分维度 |
| 综合得分 CS < 50 | 较差/极差决策（D/F） | 不推荐，需重新设计选项 |
| 一票否决V1触发（风险R≥20） | 致命风险 | 评级降为F，必须制定风险缓解方案 |
| 一票否决V2触发（价值观冲突） | 核心价值冲突 | 评级降为F，需重新审视选项 |
| 一票否决V3触发（TCO超限） | 成本不可承受 | 评级降为F，需缩减范围或寻找替代 |
| 一票否决V4触发（长期影响严重负面） | 长期不可逆损害 | 评级降为F，需重新评估长期影响 |
| 相邻选项差距 < 5 | 高度接近 | 标注"需结合场景分析"，不可仅凭分数 |
| 净收益NB > 0 但风险维度 < 50 | 高收益高风险 | 需制定风险缓解方案后再决策 |
| TCO中隐性成本占比 > 40% | 隐性成本主导 | 重新审视隐性成本估算的合理性 |
| 成本效率比CER < 1.0 | 投入大于产出 | 不推荐，除非有非量化收益补偿 |

> 知识来源: MC-147 Net-Benefit-Composite / MC-148 Risk-TCO

## 十一、可行性评估（MC-166 Feasibility-Assessment）

### 方法论原理

可行性评估的方法论基础是：**决策选项的优劣不仅取决于其理论收益，更取决于其实际可执行性——一个完美但无法执行的方案不如一个可行但不够完美的方案**。可行性评估从资源、技术、组织、时间四个维度系统检验选项的执行能力，识别执行障碍并量化执行风险。

### 执行步骤

1. **资源可行性**：评估所需资金、人力、物力是否可得
2. **技术可行性**：评估所需技术是否成熟、是否可获得
3. **组织可行性**：评估组织能力和文化是否支撑
4. **时间可行性**：评估时间约束是否可满足

### 决策规则

| 可行性评分 | 判定 | 行动 |
|-----------|------|------|
| 四维均 ≥ 7 | 高度可行 | 直接推进执行 |
| 1-2维 < 7 但 > 4 | 部分可行 | 制定针对性改进方案后推进 |
| 任一维 < 4 | 低可行性 | 暂停，先解决关键障碍 |
| 四维均 < 4 | 不可行 | 放弃该选项或彻底重新设计 |

### 输出规范

```yaml
feasibility_assessment:
  option_id: "OPT-001"
  dimensions:
    resource: {score: 1-10, gaps: ["缺口"], mitigation: "缓解措施"}
    technical: {score: 1-10, gaps: ["缺口"], mitigation: "缓解措施"}
    organizational: {score: 1-10, gaps: ["缺口"], mitigation: "缓解措施"}
    temporal: {score: 1-10, gaps: ["缺口"], mitigation: "缓解措施"}
  overall_feasibility: "high/partial/low/infeasible"
  critical_blockers: ["关键障碍"]
  recommended_action: "推进/改进后推进/暂停/放弃"
```

### 穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整四维评估 | 四维均可评分 | 完整四维评分+障碍识别+缓解方案 |
| L2 部分维度评估 | 部分维度信息不足 | 评估可得维度，缺失维度标注"未评估" |
| L3 定性可行性判断 | 无法量化评分 | 做定性可行/不可行判断，标注"定性判断" |
| L4 直觉判断 | 无足够信息 | 基于经验做直觉判断，标注"直觉判断" |

## 十二、一票否决机制（MC-169 One-Vote-Veto）

### 方法论原理

一票否决机制的方法论基础是：**某些风险或冲突的严重程度足以使任何收益都无法补偿——当存在致命缺陷时，综合评分失去意义**。一票否决不是"降低评分"，而是"否决选项"——它将选项从候选池中移除，无论其他维度得分多高。

### 决策规则

| 否决条件 | 触发阈值 | 否决后行动 |
|---------|---------|-----------|
| V1 致命风险 | 任一风险分 R ≥ 20 且无有效缓解 | 评级降为F，必须制定缓解方案后重新评估 |
| V2 核心价值观冲突 | 核心价值维度影响 ≤ -3 且不可调和 | 评级降为F，需重新审视选项或调整价值权重 |
| V3 成本不可承受 | TCO > 可承受上限150% | 评级降为F，需缩减范围或寻找替代资金 |
| V4 长期影响严重负面 | CI(10) < -0.5 且不可逆 | 评级降为F，需重新评估长期影响模型 |

### 输出规范

```yaml
one_vote_veto:
  option_id: "OPT-001"
  veto_triggered: true|false
  veto_conditions:
    V1_fatal_risk: {triggered: true|false, risk_score: 0-25, mitigation_available: true|false}
    V2_value_conflict: {triggered: true|false, impacted_dimension: "维度", impact_score: -5to5}
    V3_cost_unaffordable: {triggered: true|false, tco: 0.0, threshold: 0.0, ratio: 0.0}
    V4_long_term_damage: {triggered: true|false, ci_10: 0.0, irreversible: true|false}
  original_rating: "S+/S/A/B/C/D"
  vetoed_rating: "F"
  remediation_required: ["需制定的缓解方案"]
```

### 穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整四项否决检查 | 四项否决条件均可评估 | 完整四项检查+否决判定 |
| L2 部分否决检查 | 部分否决条件无法评估 | 检查可得项，缺失项标注"未检查" |
| L3 致命风险单项检查 | 仅可评估风险维度 | 仅做V1致命风险检查，标注"仅风险否决检查" |
| L4 无否决检查 | 无任何否决条件可评估 | 标注"未执行否决检查，综合评分可能高估" |

## 方法论知识内化

### TC-089 pyDecision多准则决策方法论

**方法论原理**：pyDecision方法论的核心认知假设是——多准则决策问题不存在"最优"解，只存在"在给定偏好结构和决策规则下最优"的解。46种MCDA方法的本质差异在于它们对偏好建模的不同假设：补偿性方法（TOPSIS/VIKOR）允许强维度补偿弱维度，非补偿性方法（ELECTRE）要求每个维度满足阈值，层次化方法（AHP/ANP）将决策结构分解为准则层级，偏序方法（PROMETHEE）保留不可比性。在五维决策矩阵引擎中，pyDecision不是替代五维评估，而是为五维评估的量化综合提供算法化执行层——当决策问题复杂度超过人工判断能力时，用MCDA方法确保评分的数学一致性和偏好透明性。

**执行步骤**：
1. 问题结构化：确定决策目标、候选方案集、评价准则集、准则权重
2. 方法选择：根据决策问题特征（补偿性需求/准则独立性/不确定性水平）选择MCDA方法
3. 决策矩阵构建：方案×准则的评价值矩阵，统一量纲（归一化/标准化）
4. 权重确定：通过AHP成对比较或直接赋权确定准则权重
5. MCDA求解：执行选定方法的计算流程
6. 敏感性分析：检验权重变化对排序结果的稳健性
7. 结果解释：输出方案排序、优劣势分析、决策建议

**决策规则**：

| 条件 | 推荐方法 | 理由 |
|------|---------|------|
| 准则间可补偿 + 需要理想解距离 | TOPSIS | 计算各方案到正/负理想解的距离，适合量化评分场景 |
| 准则间可补偿 + 需要折中解 | VIKOR | 最大化群体效用+最小化个体遗憾，适合折中决策 |
| 准则层次化 + 需要一致性检验 | AHP/ANP | 成对比较矩阵+一致性比率CR<0.1，适合结构化决策 |
| 准则不可补偿 + 需要级别优先关系 | PROMETHEE II | 偏好函数+净流量排序，保留不可比性 |
| 准则不可补偿 + 需要级别超出关系 | ELECTRE III | 否决阈值+可信度矩阵，适合非补偿性筛选 |
| 高不确定性 + 随机优势 | Stochastic MCDA | 概率分布输入+随机优势检验 |
| 准则 ≤ 5 且方案 ≤ 8 | 任意方法均可 | 问题规模小，方法差异不显著 |
| 准则 > 10 或方案 > 20 | TOPSIS/VIKOR | 计算效率高，适合大规模问题 |

**输出规范**：
```yaml
mcda_result:
  method_used: "TOPSIS|VIKOR|AHP|PROMETHEE_II|ELECTRE_III|..."
  decision_matrix:
    alternatives: [str]
    criteria: [str]
    weights: [float]
    values: [[float]]  # alternatives × criteria
  ranking:
    - {rank: int, alternative: str, score: float, confidence: float}
  sensitivity:
    weight_stability: float  # 权重变化不改变排序的容忍度
    critical_criteria: [str]  # 权重微小变化即改变排序的准则
  method_specific:
    topsis: {ideal_distances: [{alternative: str, d_plus: float, d_minus: float, closeness: float}]}
    vikor: {s_values: [float], r_values: [float], q_values: [float], v: float}
    ahp: {consistency_ratio: float, priority_vector: [float]}
    promethee: {positive_flow: [float], negative_flow: [float], net_flow: [float]}
    electre: {credibility_matrix: [[float]], outranking_relations: [[bool]]}
  exhaust_retry: "FULL|PARTIAL|MANUAL"
```

**穷尽重试策略**：当pyDecision库不可用时：L1→使用纯数学公式手动实现TOPSIS/VIKOR计算（归一化→加权→距离/排序），保留核心MCDA能力；L2→使用AHP简化版（成对比较+几何平均+归一化），仅执行层次权重计算和简单加权求和；L3→使用加权求和法（WSM）或加权积法（WPM），省略高级MCDA特性；L4→使用直觉判断+简单对比表，标注"MCDA算法不可用，决策评分基于直觉判断，可能存在偏好不一致"。

> 知识来源: TC-089 [pyDecision]
