# 多维分析框架 — 从单一维度到全面覆盖

> **模块标识**: `knowledge/thinking-models/general/multidimensional-framework`
> **来源**: TM-001 (问题树生成器)、TM-013 (因果链分析器)、TM-021 (路径依赖分析)、TM-028 (跨文化视角切换)
> **依赖**: `knowledge/research-methods`、`knowledge/cognitive-framework`
> **子模型**: `knowledge/thinking-models/general/systems-thinking`

---

## 1. 定义

多维分析框架是一种确保分析覆盖所有关键维度的系统性思维方式。它要求每个问题至少从8个基础维度（政治、经济、社会、技术、环境、法律、伦理、心理）进行审视，并通过问题树的递归分解，将每个子问题映射到最敏感的分析维度。多维分析不做"全面"的姿态——它用结构化的维度矩阵强制覆盖。

**核心法则**: 你忽视的维度，就是未来推翻你结论的维度。

## 2. 八维分析矩阵

### 2.1 八维定义

| 维度 | 编码 | 核心问题 | 关键指标 |
|------|------|---------|---------|
| **政治** | D-POL | 权力如何分配？谁有决策权？制度如何约束？ | 权力结构、决策机制、制度稳定性、利益集团 |
| **经济** | D-ECO | 资源如何配置？激励机制是什么？效率与公平？ | 供需、价格、成本、收益、市场结构、外部性 |
| **社会** | D-SOC | 人们如何组织？规范如何形成？不平等如何产生？ | 社会结构、阶层流动、文化规范、人口特征 |
| **技术** | D-TEC | 什么技术可用？技术如何改变可能空间？颠覆风险？ | 技术成熟度、扩散速度、替代风险、技术壁垒 |
| **环境** | D-ENV | 对物理/生态环境有什么影响？资源约束是什么？ | 碳排放、资源消耗、生态系统影响、可持续性 |
| **法律** | D-LEG | 法律如何规定？合规风险？权利与义务如何分配？ | 法规框架、合规成本、法律责任、知识产权 |
| **伦理** | D-ETH | 这样做对吗？公平吗？谁的利益被牺牲了？ | 公正性、透明度、知情同意、弱势群体保护 |
| **心理** | D-PSY | 人们如何感知和反应？认知偏差如何影响判断？ | 风险感知、信任度、行为偏向、心理韧性 |

### 2.2 维度敏感性矩阵

对每个分析对象，评估各维度的敏感性和影响力：

```yaml
sensitivity_matrix:
  dimensions:
    D-POL: {sensitivity: "high", impact: "high", reason: "政策变量对行业有直接定价权"}
    D-ECO: {sensitivity: "high", impact: "high", reason: "市场需求弹性大"}
    D-SOC: {sensitivity: "medium", impact: "medium", reason: "消费者偏好缓慢变化"}
    D-TEC: {sensitivity: "high", impact: "critical", reason: "颠覆性技术可能重构行业"}
    D-ENV: {sensitivity: "low", impact: "low", reason: "行业本身碳排放低"}
    D-LEG: {sensitivity: "medium", impact: "high", reason: "合规成本占总成本15%"}
    D-ETH: {sensitivity: "medium", impact: "medium", reason: "数据隐私问题受公众关注"}
    D-PSY: {sensitivity: "medium", impact: "low", reason: "消费者决策偏理性驱动"}
```

**规则**: 高敏感维度的分析深度必须 >= 低敏感维度的2倍。

## 3. 问题树生成器

### 3.1 MECE递归分解

以核心问题为根节点，按MECE原则（相互独立、完全穷尽）递归分解为子问题树。

```
根问题: "为什么X现象正在发生？"
  ├─ 直接原因层
  │   ├─ 技术驱动因素 → "核心技术发生了什么变化？"
  │   ├─ 需求驱动因素 → "用户需求发生了什么变化？"
  │   └─ 制度驱动因素 → "政策环境发生了什么变化？"
  │
  ├─ 机制原因层
  │   ├─ 正反馈机制 → "什么机制在放大变化？"
  │   ├─ 网络效应 → "使用者增加如何进一步促进使用？"
  │   └─ 锁定效应 → "什么让用户难以离开？"
  │
  └─ 结构原因层
      ├─ 基础设施 → "底层基础设施是否支撑了变化？"
      ├─ 人才供给 → "相关人才是否充足？"
      └─ 资本流向 → "资本是否向该领域集中？"
```

### 3.2 问题优先排序

对每个叶子子问题评估两项指标后排序：

```
影响度 I: 该子问题对核心问题的解释力（1-10）
不确定度 U: 该子问题的证据充分程度（10-充分确定，1-高度不确定）

处理优先级 = I × (11-U)  # 高分 = 影响力大且信息不足，优先处理
```

## 4. 跨文化/跨领域视角切换

### 4.1 切换规则

单一文化/领域视角存在系统性盲区。本机制要求：
1. 在关键分析节点自动切换至少2个不同文化/领域视角
2. 识别在原始视角下"显而易见"但在替代视角下"有问题"的假设
3. 标注视角切换揭示了什么新信息

### 4.2 视角切换清单

| 切换类型 | 示例视角对 | 关注差异 |
|---------|-----------|---------|
| 文化切换 | 西方 ↔ 东方 | 个体vs集体、规则vs关系、短期vs长期 |
| 学科切换 | 经济学 ↔ 社会学 | 理性选择vs规范约束、效率vs公平 |
| 层级切换 | 全球 ↔ 本地 | 趋势vs具体、普遍vs特殊 |
| 时间切换 | 当代 ↔ 历史 | 当前合理性vs历史偶然性 |
| 立场切换 | 掌权者 ↔ 弱势者 | 秩序维护vs公正诉求 |

## 5. 路径依赖分析

### 5.1 核心概念

当前状态并非由"最佳选择"决定，而是由历史选择的累积锁定决定。路径依赖分析追溯"是什么让系统沿着当前路径走了这么远，为什么没有走另一条路？"

### 5.2 分析步骤

1. **识别关键分叉点**: 历史上在某几个节点上存在不同路径可能性
2. **分析选择机制**: 在分叉点，什么因素导致了最终的选择？（经济/政治/偶然）
3. **分析锁定机制**: 一旦走上这条路径，什么机制阻止了切换？（沉没成本/网络效应/制度惯性/认知锁定）
4. **评估锁定强度**: 当前锁定有多强？切换成本有多大？
5. **识别解锁条件**: 什么条件可能触发路径切换？

## 6. 常见陷阱

1. **维度覆盖仪式化**: 每个维度都写了但都只是皮毛，高敏感维度被平均对待。**纠正**: 使用敏感性矩阵强制高敏感维度翻倍深度。
2. **MECE失败**: 子问题之间有重叠（不互斥）或遗漏（不穷尽）。**纠正**: 交叉检查——每个子问题都可以归类到单一视角吗？所有可能的解释维度都有对应的子问题吗？
3. **跨文化切换流于表面**: 将"在其他文化中"等同于"在其他国家中"，忽略文化内部的多样性。**纠正**: 选择一个特定文化语境进行深度介入，而非泛泛而谈"在东方文化中"。
4. **路径依赖的事后合理化**: 因为事情这样发生了，就认为它必然这样发生，忽略分叉点的偶然性。**纠正**: 对每个分叉点构建至少一个可能但未发生的替代路径。

## 8. 内化方法论：八维交叉影响分析（Cross-Dimension-Correlation）

### 方法论原理

八维交叉影响分析的方法论基础是：**维度之间不是独立的——一个维度的变化会通过因果链或相关链影响其他维度，而这些跨维度影响往往是分析中最容易被忽略也最具有颠覆性的**。例如，技术变化（D-TEC）不仅直接影响技术维度，还通过改变就业结构影响经济维度（D-ECO），通过改变社交方式影响社会维度（D-SOC），通过创造新的监管需求影响法律维度（D-LEG）。如果不显式构建8×8的交叉影响矩阵，分析者将系统性地低估维度间的连锁效应，导致"单维度深挖但忽略跨维度传导"的盲区。进一步，区分因果链（A导致B）和相关链（A和B有共同原因C）对于正确预测至关重要——基于相关链的干预不会产生预期效果。

### 执行步骤

1. **构建8×8交叉影响矩阵**：以八维（D-POL, D-ECO, D-SOC, D-TEC, D-ENV, D-LEG, D-ETH, D-PSY）为行和列，形成64个交叉单元格。对每个单元格 (D_i, D_j)，评估维度 D_i 的变化对维度 D_j 的影响
2. **关联强度判定**：对每个非对角线单元格，判定关联强度：
   - **强关联（++/--）**：D_i 的变化必然导致 D_j 的显著变化，且影响方向确定（++为同向，--为反向）
   - **中关联（+/-）**：D_i 的变化通常导致 D_j 的可观察变化，但影响可能被其他因素缓冲
   - **弱关联（~）**：D_i 的变化在特定条件下可能影响 D_j，但一般情况下影响可忽略
   - **无关联（0）**：D_i 与 D_j 之间无已知的影响关系
3. **因果链vs相关链区分**：对每个非零关联，判定其性质：
   - **因果链**：D_i 的变化直接导致 D_j 的变化（存在可识别的因果机制）。检验方法：如果干预 D_i 而 holding 其他所有因素不变，D_j 是否变化？若是，则为因果链
   - **相关链**：D_i 和 D_j 的变化由共同原因 D_k 驱动，或 D_i 和 D_j 互为结果。检验方法：如果控制 D_k 后 D_i 和 D_j 的关联消失，则为相关链（伪相关）
   - **双向因果**：D_i 和 D_j 互为因果（正反馈或负反馈回路）
4. **高敏感维度识别**：计算每个维度的"敏感度"= 该维度受其他维度影响的强度之和（行方向的强关联数×2 + 中关联数×1）。敏感度最高的维度为"高敏感维度"——它最容易被其他维度的变化所改变，因此是需要重点监测的"早期预警维度"
5. **高影响力维度识别**：计算每个维度的"影响力"= 该维度对其他维度影响的强度之和（列方向的强关联数×2 + 中关联数×1）。影响力最高的维度为"高影响力维度"——改变它将产生最大的连锁效应，因此是干预的"杠杆点"
6. **关键路径识别**：从矩阵中提取影响强度最高的3-5条跨维度路径（如 D-TEC → D-ECO → D-SOC → D-POL），标注为"关键传导路径"
7. **反馈回路检测**：检查矩阵中是否存在闭环路径（如 D-ECO → D-POL → D-LEG → D-ECO），标注为"正反馈回路"（放大效应）或"负反馈回路"（稳定效应）

### 决策规则

| 关联强度 | 判定 | 分析要求 |
|---------|------|---------|
| 强关联 | 必须深入分析跨维度传导机制 | 产出完整的因果链描述和量级估计 |
| 中关联 | 需要分析但可接受定性评估 | 产出方向性判断和量级范围 |
| 弱关联 | 快速标注即可 | 仅标注存在性和方向 |
| 无关联 | 不需要跨维度分析 | 标注"0"即可 |

| 因果性质 | 判定 | 干预含义 |
|---------|------|---------|
| 因果链 | D_i 直接导致 D_j | 干预 D_i 可有效影响 D_j |
| 相关链 | D_i 和 D_j 有共同原因 | 干预 D_i 不会影响 D_j，需找到共同原因 |
| 双向因果 | D_i 和 D_j 互为因果 | 干预任一维度都会产生反馈效应，需系统视角 |
| 未确定 | 无法判定因果/相关 | 标注"未确定"，不基于此做干预预测 |

| 维度类型 | 识别标准 | 策略含义 |
|---------|---------|---------|
| 高敏感维度 | 敏感度排名前2 | 作为早期预警指标重点监测 |
| 高影响力维度 | 影响力排名前2 | 作为干预杠杆点优先考虑 |
| 高敏感+高影响力 | 同时排名前2 | 系统的关键枢纽，任何变化都将产生巨大连锁效应 |

### 穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整8×8矩阵 | 所有64个交叉影响可评估 | 完整执行7步，输出精确矩阵和排名 |
| L2 部分矩阵 | 部分维度间关系不可评估 | 评估可得关系，不可评估的单元格标注"未评估"，排名标注"部分评估" |
| L3 关键路径分析 | 无法构建完整矩阵但可识别关键路径 | 仅识别和描述3-5条最关键的跨维度路径，不做完整矩阵 |
| L4 定性交叉检查 | 无量化数据 | 对每对维度做定性影响判断（增强/减弱/无关），不做强度量化 |
