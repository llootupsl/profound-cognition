# 第一性原理 — 追溯至不可再分的基本事实

> **模块标识**: `knowledge/thinking-models/general/first-principles`
> **来源**: TM-004 (第一性原理拆解器)、T04 (认知流水线第一性原理拆解器)
> **依赖**: `knowledge/research-methods`、`knowledge/cognitive-framework`
> **父模型**: `knowledge/thinking-models/general/critical-thinking`

---

## 1. 定义

第一性原理是一种将复杂问题逐层拆解，直到抵达不可再分的基本事实或公理的思维方式。它要求分析者摒弃"因为别人都这样做"或"一直是这样"的类比推理，转而追问"这个结论的基本构造块是什么？"每一个推导出的原理必须锚定于至少一个公理级的基本事实。

**核心法则**: 如果你的分析有5层推理，第5层必须仍然锚定于第1层的基本事实，而非浮在中间层的未验证假设上。

---

## 2. 核心概念

| 概念 | 定义 | 示例 |
|------|------|------|
| **公理** | 不可再分的、广泛验证的基本事实 | "能量守恒"是物理学的公理 |
| **派生原理** | 从公理通过可验证逻辑推导出的原理 | "电池容量受限于材料能量密度" |
| **浮动假设** | 被当作事实使用但未验证的命题 | "市场会自然选择最优方案" |
| **锚定验证** | 检查每个派生原理是否可追溯到公理 | 追溯 "我们的方案可行" 的推理链 |

---

## 3. 执行流程

```
问题输入 → 拆解为组成元件 → 对每个元件追问"这是什么构成的？"
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
            自证真理性      可继续拆解        不确定
           (即为公理)     (追问下一层)    (标记为浮动假设)
                    │               │               │
                    └───────────────┼───────────────┘
                                    ▼
                    输出: 公理集 + 派生原理链 + 浮动假设清单
```

### 3.1 拆解规则

1. **追问"为什么"直到不能再问**: 每个"为什么"的答案都成为下一轮"为什么"的问题。当答案是"因为这本身就是事实"或"这是已验证的物理/数学/逻辑定律"时，到达公理层。
2. **区分相关性拆解与因果性拆解**: "问题A由哪些部分构成"（相关性拆解）与"什么导致了问题A"（因果性拆解）是两种不同的拆解路径，必须分别执行。
3. **标注每个节点的验证状态**: 已验证/基于现有研究/基于逻辑推导/基于假设/未验证。

### 3.2 公理验证标准

一个命题必须同时满足以下条件才能被认定为公理：
- 广泛性: 在多个独立来源中被一致确证
- 稳定性: 在时间跨度和条件变化下保持成立
- 可证伪性: 可以明确描述什么证据会推翻它
- 不可再分性: 无法进一步拆解为更基础的命题

---

## 4. 常见陷阱

1. **伪公理化**: 将"行业共识"或"普遍做法"当作公理，而非根本事实。**纠正**: 检查是否有比"大家认为"更基础的事实支撑。
2. **拆解层级不足**: 在到达真正的基本事实之前停止拆解。**纠正**: 每层拆解后追问"这又是由什么构成的？"
3. **混淆解释与描述**: "这个系统很复杂"是描述不是解释——不是公理。**纠正**: 解释必须包含因果机制或构成机制。
4. **阈下假设**: 在没有意识到的情况下引入未验证假设。**纠正**: 对每个"因为"后面的命题检查验证状态。

## 6. 与递归深挖引擎的协同

第一性原理拆解完成后，输出自动送入递归深挖引擎的 L4 因果推理层。未被拆解到公理层的浮动假设自动触发新的递归深挖分支。

## 7. 第一性原理决策规则

| 条件 | 判定 | 行动 |
|------|------|------|
| 所有派生原理均可追溯到公理 | 锚定完整 | 论证体系基础可靠 |
| 存在浮动假设且 criticality 高 | 锚定不完整 | 必须验证浮动假设或将其穷尽重试为"工作假设" |
| 公理验证四标准全部通过 | 公理可靠 | 可基于公理继续推理 |
| 公理存在"伪公理化"风险 | 公理不可靠 | 穷尽重试为"工作假设"，重新寻找更基础的事实 |
| 拆解层级 < 3 且存在未验证中间层 | 拆解不足 | 继续追问"为什么"直到不可再分 |
| 因果性拆解与相关性拆解混淆 | 拆解方向错误 | 分别执行两种拆解路径 |

> 知识来源: MC-158 Axiom-Verification

## 8. 第一性原理穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整第一性原理拆解 | 问题可逐层拆解至公理 | 完整拆解+公理验证+浮动假设标注 |
| L2 部分拆解 | 部分层级无法继续拆解 | 对可拆解部分做完整分析，不可拆解部分标注"拆解中断" |
| L3 因果链分析 | 无法做完整拆解但可识别因果链 | 做因果链分析，标注"非第一性原理拆解" |
| L4 要素列举 | 仅可列举问题组成要素 | 列举要素和已知关系，标注"仅结构识别" |

## 9. 内化方法论：层层剥落分析（MC-162 Layer-Peeling）

### 方法论原理

层层剥落分析的方法论基础是：**复杂问题的核心真相往往被多层表象、惯例和假设所包裹——如同洋葱，必须逐层剥去外层才能触及核心**。与第一性原理的"追问为什么"不同，层层剥落侧重于"识别并移除遮蔽层"——每一层遮蔽可能是一个行业惯例、一个未经检验的假设、一个过时的范式。这一方法论之所以必要，是因为最常见的分析失败不是"没想到"，而是"想到了但被表层惯例遮蔽了"——行业惯例和思维定势形成了自动过滤机制，阻止分析者看到核心问题。

### 执行步骤

1. **表层识别**：识别问题最外层的描述框架和惯例性解释
2. **表层移除**：暂时搁置表层解释，追问"如果这个解释不成立呢？"
3. **次层识别**：在移除表层后，识别下一层的假设和框架
4. **逐层剥落**：重复步骤2-3，直到抵达无法再移除的核心层
5. **核心层验证**：对核心层做公理验证（参照第一性原理的公理验证标准）
6. **重建分析**：从核心层出发，重新构建分析框架

### 决策规则

| 剥落结果 | 判定 | 行动 |
|---------|------|------|
| 剥落3层以上才抵达核心 | 问题被深度遮蔽 | 需警惕行业惯例的系统性偏误 |
| 每层剥落后结论变化显著 | 表层遮蔽严重 | 核心层结论与表层结论差异大，以核心层为准 |
| 剥落2层后结论不再变化 | 遮蔽较浅 | 核心层与表层差异不大，可适当简化分析 |
| 无法识别下一层 | 已抵达核心或分析能力不足 | 做公理验证，若通过则为核心层 |

### 输出规范

```yaml
layer_peeling_analysis:
  problem: "分析问题"
  layers:
    - level: 1
      description: "表层描述/惯例"
      assumption: "该层隐含的假设"
      removed: true|false
      reason_for_removal: "移除理由"
    - level: 2
      description: "次层描述"
      assumption: "该层隐含的假设"
      removed: true|false
      reason_for_removal: "移除理由"
  core_layer:
    description: "核心层描述"
    verification_status: "verified/unverified"
    conclusion_shift: "核心层结论与表层结论的差异"
  rebuilt_framework: "从核心层重建的分析框架"
```

### 穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整层层剥落 | 可识别多层遮蔽并逐层移除 | 完整6步，输出核心层和重建框架 |
| L2 部分剥落 | 部分层次无法识别 | 对可识别层做剥落，不可识别层标注"层次不明" |
| L3 表层质疑 | 仅可识别和移除表层 | 做表层质疑，标注"仅表层剥落" |
| L4 问题重构 | 无法做层次分析 | 重新表述问题，标注"无层次分析" |
