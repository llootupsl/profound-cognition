## 1. 定义

批判性思维是一种系统性地检验信念可靠性的思维纪律。它包含三条并行的工作线：(1) 挖掘隐藏假设——每个主张背后未言明的前提是什么；(2) 反事实推演——如果前提不成立，后果是什么；(3) 认知偏误检测——我的思维过程在哪里可能被系统性扭曲。批判性思维的终点不是虚无主义——而是经过严格检验后的审慎确信。

**核心法则**: 你最确定的东西，最需要被检验。

## 2. 三层假设挖掘框架

### 2.1 三层分类

```
表面层（显性假设）
  ├─ 已明确声明的假设前提
  └─ 特征: 可以在文本中直接定位
        │
        ▼
潜层（隐性假设）
  ├─ 未声明但逻辑推导所需的预设
  └─ 特征: 去掉这个假设后论证不成立，但论证者未意识到
        │
        ▼
深层（隐藏假设）
  ├─ 论证者本人也未意识到的、根植于世界观/范式的预设
  └─ 特征: 被整个共同体视为"理所当然"，甚至不是可选项
```

### 2.2 挖掘算法

```
输入: 一个论证或主张
  │
  ▼
步骤1: 定位显性假设 → 扫描"假设"、"前提"、"给定"、"因为"等标记词
  │
  ▼
步骤2: 倒推隐性假设 → 对每个断言追问"要得出这个结论，什么必须为真？"
  │
  ▼
步骤3: 世界观审计 → 将分析对象放置在不同文化/范式背景下观察
  │ 哪些在原始语境中被视为"理所当然"的东西在此背景下不再是？
  │
  ▼
步骤4: 假设排序 → 按 criticality × uncertainty 排序
  │ 高关键性 + 高不确定性 = 必须优先验证
  ▼
输出: 假设地图（3层标注 + 优先级排序）
```

### 2.3 假设临界性评估

```
criticality = 该假设对结论的支撑力度（若假设为假，结论被削弱或推翻的程度）
uncertainty = 该假设的证据支持度（低不确定性 = 有强证据支持）

criticality 高 + uncertainty 高 → 红色标记（结论的致命弱点，必须验证）
criticality 高 + uncertainty 低 → 绿色标记（关键但已有牢固支持）
criticality 低 + uncertainty 高 → 黄色标记（次要不确定性，可标注后接受）
criticality 低 + uncertainty 低 → 灰色标记（低优先级）
```

## 3. 反事实推演框架

### 3.1 七种反事实类型

| 类型 | 干预对象 | 核心问题 |
|------|---------|---------|
| 前提反事实 | 核心假设 | "如果关键前提不成立，结论还成立吗？" |
| 变量反事实 | 关键变量 | "如果某个关键变量取反值，结果如何？" |
| 时序反事实 | 事件顺序 | "如果事件发生的顺序/时机不同呢？" |
| 主体反事实 | 行动者 | "如果决策者/行动者不同呢？" |
| 因果反事实 | 因果链 | "如果某因果环节断裂呢？" |
| 制度反事实 | 游戏规则 | "如果制度/法律框架不同呢？" |
| 极端反事实 | 全部前提 | "在最极端的反向假设下，结论的边界在哪？" |

### 3.2 推演标准

每个反事实推演必须包含：
- 被改变的具体变量/前提
- 推演的因果链（至少3步）
- 与新事实矛盾的证据
- 反事实结论对原始结论的影响评估（翻转/削弱/不变/加强）

### 3.3 鲁棒性压力测试

对结论进行系统性压力测试：

| 测试类型 | 操作 | 通过标准 |
|---------|------|---------|
| 极端参数测试 | 将关键参数推到极端值 | 结论在极端值下不翻转 |
| 假设移除测试 | 逐个移除支撑假设 | 识别核心支撑假设的最低集合 |
| 证据等级穷尽重试 | 将支撑证据从"已确认"穷尽重试至"推断" | 结论可信度不降至50%以下 |
| 时序反转测试 | 反转关键事件的时序 | 结论的因果方向不被反转 |
| 范式外测试 | 在完全不同的分析范式下检验 | 结论在不同范式下仍有解释力 |

## 4. 认知偏误全扫描

### 4.1 扫描清单

| 编号 | 偏误名称 | 检测问题 |
|------|---------|---------|
| B1 | 确认偏误 | 是否在主动寻找支持已有判断的证据而忽略反证？ |
| B2 | 锚定效应 | 初始信息是否过度影响了后续判断？ |
| B3 | 框架效应 | 相同信息的不同表述方式是否改变了你的判断？ |
| B4 | 可得性启发 | 是否因某些案例更易回忆而高估其概率？ |
| B5 | 过度自信 | 置信度是否与证据支撑度匹配？ |
| B6 | 幸存者偏差 | 是否只看到了成功的案例而忽略了大量失败？ |
| B7 | 归因偏差 | 是否将成功归因于内在因素、失败归因于外部？ |
| B8 | 后见之明 | 是否在事后将本来不确定的事视为"显而易见"？ |
| B9 | 群体思维 | 是否因为"大家都这么想"而放弃独立思考？ |
| B10 | 沉没成本 | 是否因为已投入资源而坚持错误方向？ |
| B11 | 计划谬误 | 是否系统性地低估了实现的时间和成本？ |

### 4.2 偏误缓解策略

- 主动寻找反面证据（对抗确认偏误）
- 多版本表述同一问题（对抗框架效应）
- 调整基准率校准（对抗可得性启发）
- 独立估算后平均（对抗锚定效应）
- 前提验尸分析（对抗过度自信）——假设结论已被证明是错的，追溯错在哪里

## 5. 苏格拉底式诘问

### 5.1 追问豁免清单

以下追问方向不可因"显然"、"常识"、"大家都知道"而被豁免：

1. "你说的这个概念，能给我一个精确的定义吗？"
2. "这个主张的证据链是什么？每一个环节都可独立检验吗？"
3. "在什么情况下这个主张不成立？给我一个具体的反例条件。"
4. "这个主张导致的实际行为推论是什么？如果人们相信它，他们会做什么？"
5. "这个主张预设了哪些未声明的立场和价值判断？"

### 5.2 追问结束条件

苏格拉底式诘问在以下条件同时满足时结束：
- 回答者抵达了"我再无法进一步解析的出发点"（公理或基本价值观）
- 该出发点已被明确标注为出发点（而非伪装为推论）
- 诘问者确认了该出发点的"如果出发点是错的"的全部推论

### 5.3 范式质疑框架

在苏格拉底式诘问无法通过基本假设继续深入时，启动更高级的范式质疑：

**三层范式质疑**:
1. **问题框架层面**: "这个问题本身是否预设了某种立场？换一种框架，同样的事实会被如何理解？"
2. **方法框架层面**: "为什么选这种分析方法？该方法本身的局限是什么？"
3. **价值观框架层面**: "分析中隐含了谁的价值观？不同价值观体系下，结论是否一致？"

## 6. 常见陷阱

1. **假设挖掘仪式化**: 列出一堆假设但不评估关键性，不区分红色假设和灰色假设。**纠正**: 对每个假设标注 criticality × uncertainty 矩阵。
2. **假反事实**: 表面上做了反事实，但只推演了与原结论一致的方向。**纠正**: 反事实必须推演到结论可能被翻转的方向为止。
3. **偏误检测的自指问题**: "我做偏误检测时就没有偏误吗？" 对自己判断的偏误扫描一样会受偏误影响。**纠正**: 偏误检测结论本身也需要被标注为"推断"，而非"已确认"。
4. **苏格拉底式诘问沦为文字游戏**: 在定义层面无限循环，不产生新洞见。**纠正**: 当连续3轮追问无信息增量时，切换到实证方向："什么观察可以裁定这个争论？"

## 8. 内化方法论：公理验证（Axiom-Verification）

### 方法论原理

公理验证的方法论基础是：**任何论证体系都建立在公理（不可再分解的出发点）之上，而论证的可靠性最终取决于其公理的可靠性**。公理验证不是质疑一切——而是系统性地检验论证的出发点是否值得信赖。公理验证四标准（自洽性、独立性、完备性、一致性）来自数学基础研究的元数学传统，将其应用于一般论证分析，可以精确识别论证体系的结构性弱点。这一方法论之所以必要，是因为最常见的论证失败不是推理过程的错误，而是出发点的缺陷——一个从错误公理出发的完美推理，只会更高效地得出错误结论。

### 执行步骤

1. **识别公理层**：对目标论证体系，逐层追问"为什么"直到抵达无法进一步分解的出发点。这些出发点即为公理。标注每个公理的类型：事实公理（经验判断）、逻辑公理（推理规则）、价值公理（规范性判断）
2. **自洽性检验**：检查公理集合内部是否存在矛盾。对每对公理 (A_i, A_j)，假设两者同时为真，推导是否产生矛盾。若产生矛盾，标记为"自洽性失败"，该公理集合不可用
3. **独立性检验**：检查每个公理是否可从其他公理推导得出。对每个公理 A_i，假设 A_i 为假而其余公理为真，检查是否可推导出 A_i。若可推导，A_i 非独立（冗余），标注但非致命问题；若不可推导，A_i 独立（必要），标注为"核心公理"
4. **完备性检验**：检查公理集合是否足以支撑论证体系的所有结论。对论证中的每个关键结论 C_k，追溯其推导链，检查是否每一步都有公理支撑。若存在无公理支撑的推导步骤，标注为"完备性缺口"
5. **一致性检验**：检查公理集合是否与已知事实/外部知识一致。对每个公理 A_i，搜索是否存在与 A_i 矛盾的可靠外部证据。若存在，标注为"一致性风险"
6. **递归拆解**：若公理本身仍可被质疑（即它不是真正的"不可再分解"出发点），则对该公理启动新一轮公理验证（递归）。递归深度上限为3层，超过3层标注为"公理链过深，需接受为工作假设"
7. **验证结果汇总**：对所有公理标注验证状态，计算公理集合的整体可靠性评分

### 决策规则

| 验证结果 | 判定 | 行动 |
|---------|------|------|
| 四标准全部通过 | 公理集合可靠 | 论证体系的基础可信，可继续推理 |
| 自洽性失败 | 公理集合不可用 | 必须修改或删除矛盾公理，否则论证无效 |
| 完备性缺口存在 | 公理集合不足 | 补充缺失公理或标注结论为"条件性成立" |
| 一致性风险存在 | 公理与外部证据冲突 | 穷尽重试该公理为"待验证假设"，基于该公理的结论置信度降低 |
| 独立性失败（冗余公理） | 非致命问题 | 删除冗余公理简化体系，但不影响论证有效性 |
| 递归深度 > 3 | 公理链过深 | 接受最底层为"工作假设"，标注"不可进一步验证" |
| 事实公理与价值公理混淆 | 范畴错误 | 必须分离：事实公理可被证据检验，价值公理只能被价值论证检验 |

### 穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整四标准验证 | 公理可明确识别且外部证据可得 | 完整执行7步，输出精确验证结果 |
| L2 三标准验证 | 外部证据不可得（无法做一致性检验） | 跳过一致性检验，仅做自洽性+独立性+完备性，标注"一致性未验证" |

| L4 定性评估 | 公理无法明确枚举 | 基于论证整体做定性公理审查，标注"非形式化验证" |

## 9. 内化方法论：MECE优先级排序（MECE-Prioritization）

### 方法论原理

MECE优先级排序的方法论基础是：**分析的质量不仅取决于"想到了什么"，更取决于"先想什么、后想什么、忽略什么"**。MECE（Mutually Exclusive, Collectively Exhaustive）递归分解确保分析覆盖的完备性和不重叠性，而优先级排序确保有限认知资源被分配到最有价值的分析方向。这一方法论之所以必要，是因为最常见的分析失败不是"没想到"，而是"想到了但没来得及深入"——在有限时间内平均分配精力导致所有方向都浅尝辄止。八维分析矩阵（政治、经济、社会、技术、环境、法律、伦理、心理）为MECE分解提供了维度框架，而优先级公式（I × (11-U)）为排序提供了量化标准。

### 执行步骤

1. **定义核心问题**：将分析目标表述为一个明确的疑问句，确保问题边界清晰（"X现象的原因是什么？"而非"关于X"）
2. **MECE递归分解**：
   - 第一层分解：按八维矩阵（D-POL, D-ECO, D-SOC, D-TEC, D-ENV, D-LEG, D-ETH, D-PSY）将核心问题分解为8个子问题
   - 检验MECE性：每个子问题是否可唯一归类到单一维度（互斥性）？所有可能的解释维度是否都有对应子问题（穷尽性）？
   - 第二层分解：对每个子问题继续按MECE原则分解为更细的子问题，递归深度通常为2-3层
   - 每层分解后重新检验MECE性
3. **影响度评估**：对每个叶子子问题，评估其对核心问题的解释力 I（1-10分）。I=10表示该子问题单独即可解释核心问题的绝大部分；I=1表示该子问题几乎不影响核心问题
4. **不确定度评估**：对每个叶子子问题，评估其证据充分程度 U（1-10分）。U=10表示已有充分证据和确定结论；U=1表示完全不确定、无证据
5. **优先级计算**：处理优先级 P = I × (11 - U)。高分 = 影响力大且信息不足，最优先处理；低分 = 影响力小或已充分确定，可延后
6. **排序与资源分配**：按优先级从高到低排序子问题，将80%的分析资源分配给前20%的高优先级子问题（帕累托原则），剩余20%资源覆盖其余80%子问题
7. **动态调整**：在分析过程中，随着新证据的获取，更新 I 和 U 值，重新计算优先级，动态调整资源分配

### 决策规则

| 优先级区间 | 分类 | 资源分配 | 处理方式 |
|-----------|------|---------|---------|
| P ≥ 70 | 关键优先 | 分配40%资源 | 必须深入分析，产出确定性结论 |

## 10. 内化方法论：价值-影响衰减分析（MC-149 Value-Impact-Attenuation）

### 方法论原理

价值-影响衰减分析的方法论基础是：**决策选项的价值影响不是恒定的，而是随时间、距离和规模衰减——近处的影响被高估，远处的影响被低估**。这一方法论之所以必要，是因为最常见的决策偏误是"时间贴现不一致"和"空间影响衰减忽视"——人们系统性地高估短期直接影响而低估长期间接影响，导致决策短视。

### 执行步骤

1. **影响时间线映射**：对每个决策选项，映射1年/3年/5年/10年的影响轨迹
2. **衰减率评估**：评估正面影响和负面影响的衰减速率（λ_pos, λ_neg）
3. **累积影响计算**：计算时间加权的累积影响 CI(T)
4. **衰减不对称检测**：若负面影响衰减慢于正面影响（λ_neg < λ_pos），标注"衰减不对称风险"
5. **决策修正**：基于衰减分析调整决策权重，增加长期影响的权重

### 决策规则

| 衰减模式 | 判定 | 行动 |
|---------|------|------|
| 正面影响衰减慢、负面影响衰减快 | 良性衰减 | 决策价值随时间增加，推荐长期执行 |
| 正面影响衰减快、负面影响衰减慢 | 恶性衰减 | 决策价值随时间降低，需谨慎评估 |
| 两者衰减速率相近 | 中性衰减 | 关注累积量级而非衰减率 |
| 负面影响不衰减（λ_neg ≈ 0） | 持久损害 | 触发一票否决预警 |

### 输出规范

```yaml
value_impact_attenuation:
  option_id: "OPT-001"
  impact_timeline:
    year_1: {positive: 0.0, negative: 0.0, net: 0.0}
    year_3: {positive: 0.0, negative: 0.0, net: 0.0}
    year_5: {positive: 0.0, negative: 0.0, net: 0.0}
    year_10: {positive: 0.0, negative: 0.0, net: 0.0}
  decay_rates: {lambda_positive: 0.0, lambda_negative: 0.0}
  cumulative_impact: 0.0
  attenuation_asymmetry: "benign/malignant/neutral"
  decision_adjustment: "建议的决策权重调整"
```

### 穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整衰减分析 | 时间线可映射、衰减率可评估 | 完整5步，输出衰减曲线和决策修正 |
| L2 定性衰减评估 | 衰减率无法量化 | 定性评估衰减方向（快/慢/持平），标注"定性衰减" |
| L3 时间线列举 | 仅可列举时间节点影响 | 列举各时间点影响值，标注"无衰减建模" |
| L4 影响方向标注 | 仅知影响方向 | 标注正/负方向，标注"无衰减分析" |

## 11. 内化方法论：假设-反事实推演（MC-155 Assumption-Counterfactual）

### 方法论原理

假设-反事实推演的方法论基础是：**论证的可靠性取决于其关键假设的可靠性，而检验假设最有效的方法是构造反事实——如果该假设不成立，结论会发生什么变化**。这一方法论将假设挖掘和反事实推演整合为统一流程：先挖掘假设，再对每个关键假设构造反事实，最后评估反事实对结论的影响。这一方法论之所以必要，是因为单独的假设挖掘容易流于"列举仪式"，而单独的反事实推演容易脱离论证结构——两者结合才能精确识别论证的脆弱环节。

### 执行步骤

1. **假设挖掘**：使用三层假设挖掘框架（§2），识别显性/隐性/深层假设
2. **假设排序**：按 criticality × uncertainty 排序，聚焦红色假设
3. **反事实构造**：对每个红色假设，构造"如果该假设为假"的反事实场景
4. **反事实推演**：对每个反事实，推演至少3步因果链
5. **影响评估**：评估反事实对原始结论的影响（翻转/削弱/不变/加强）
6. **鲁棒性判定**：若任一红色假设的反事实翻转结论 → 标注"结论脆弱"

### 决策规则

| 反事实影响 | 判定 | 行动 |
|-----------|------|------|
| 结论被翻转 | 致命脆弱 | 必须验证该假设，否则结论不可信 |
| 结论被显著削弱 | 重要脆弱 | 需验证该假设，降低结论置信度 |
| 结论基本不变 | 鲁棒 | 该假设非关键支撑，可接受不确定性 |
| 多个反事实均翻转结论 | 极度脆弱 | 重新构建论证体系 |

### 输出规范

```yaml
assumption_counterfactual:
  assumptions:
    - id: "ASM-001"
      statement: "假设陈述"
      layer: "explicit/implicit/hidden"
      criticality: "high/medium/low"
      uncertainty: "high/medium/low"
      risk_label: "red/yellow/green/gray"
  counterfactuals:
    - assumption_id: "ASM-001"
      counterfactual: "如果该假设为假"
      causal_chain: ["推演步骤1", "推演步骤2", "推演步骤3"]
      impact: "conclusion_flipped/conclusion_weakened/conclusion_unchanged/conclusion_strengthened"
  robustness_verdict: "robust/moderately_fragile/fragile/extremely_fragile"
  critical_assumptions_to_verify: ["必须验证的假设ID"]
```

### 穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整假设-反事实 | 假设可挖掘、反事实可推演 | 完整6步，输出鲁棒性判定 |
| L2 部分反事实推演 | 部分假设无法构造反事实 | 对可推演假设做反事实，其余标注"反事实不可构造" |
| L3 假设挖掘+定性反事实 | 反事实无法推演因果链 | 做假设挖掘+定性影响判断，标注"定性反事实" |
| L4 仅假设挖掘 | 无法构造反事实 | 仅做假设挖掘和排序，标注"无反事实推演" |

## 12. 内化方法论：偏见-苏格拉底扫描（MC-156 Bias-Socratic-Scan）

### 方法论原理

偏见-苏格拉底扫描的方法论基础是：**认知偏误检测和苏格拉底式诘问是互补的认知审计工具——偏误扫描识别系统性思维扭曲，苏格拉底诘问则深入追问扭曲的根源**。单独的偏误扫描容易停留在"贴标签"层面（"这里有确认偏误"），而不追问"为什么我会产生确认偏误？我的什么立场导致了选择性注意？"；单独的苏格拉底诘问则可能忽略系统性的认知偏误模式。两者结合形成"扫描→定位→追问→纠正"的完整认知审计闭环。

### 执行步骤

1. **偏误扫描**：使用11项偏误清单（§4.1）进行系统扫描
2. **偏误定位**：对每个检出的偏误，定位其在论证中的具体位置
3. **苏格拉底追问**：对每个偏误，启动追问链：
   - "我为什么会产生这个偏误？"
   - "我的什么立场/利益/经验导致了选择性注意？"
   - "如果我是对方，我会怎么看同一组证据？"
4. **偏误根源识别**：将偏误追溯到其认知根源（动机性推理/认知吝啬/社会从众等）
5. **纠正方案**：针对根源制定纠正策略（不仅是"注意偏误"，而是"改变产生偏误的条件"）

### 决策规则

| 偏误严重度 | 苏格拉底追问深度 | 纠正要求 |
|-----------|----------------|---------|
| 高严重度偏误（影响核心结论） | 追问至根源 | 必须改变分析条件（如引入对立证据、更换分析框架） |
| 中严重度偏误（影响部分结论） | 追问至动机层 | 标注偏误并降低受影响结论的置信度 |
| 低严重度偏误（影响边缘结论） | 快速追问 | 标注偏误，不调整结论 |

### 输出规范

```yaml

  bias_scan_results:
    - bias_type: "B1-B11"
      location: "论证中的位置"
      severity: "high/medium/low"
      detected_evidence: "检测证据"
  socratic_inquiry:
    - bias_type: "B1-B11"
      question_chain: ["追问链"]
      root_cause: "偏误根源"
      perspective_shift: "视角转换后的新理解"
  corrections:
    - bias_type: "B1-B11"
      correction_type: "条件改变/置信度调整/标注"
      action_taken: "已执行的纠正"
  scan_limitation: "扫描本身的偏误局限声明"
```

### 穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整偏误扫描+苏格拉底追问 | 偏误可检测、追问可执行 | 完整5步，输出偏误根源和纠正方案 |
| L2 偏误扫描+浅层追问 | 追问无法深入到根源 | 做偏误扫描+1-2轮追问，标注"追问深度不足" |
| L3 仅偏误扫描 | 无法执行苏格拉底追问 | 做11项偏误扫描，标注"无追问环节" |
| L4 偏误清单自查 | 无条件做系统扫描 | 使用偏误清单做自查，标注"自查非系统扫描" |

## 13. 内化方法论：鲁棒性压力测试（MC-157 Robustness-Stress-Test）

### 方法论原理

鲁棒性压力测试的方法论基础是：**结论的可靠性不仅取决于正常条件下的表现，更取决于极端条件下的稳定性——一个只在理想条件下成立的结论，其可靠性远低于在各种扰动下仍保持的结论**。压力测试通过系统性地将关键参数推至极端、移除支撑假设、穷尽重试证据等级检验，检验结论的边界条件。这一方法论之所以必要，是因为最常见的过度自信来源于"只在正常条件下验证"——当条件偏离预期时，结论可能突然失效。

### 执行步骤

1. **极端参数测试**：将关键参数推至极端值（±2σ或更极端），观察结论是否翻转
2. **假设移除测试**：逐个移除支撑假设，识别结论依赖的核心假设最小集
3. **证据等级穷尽重试测试**：将支撑证据从"已确认"穷尽重试至"推断"→"猜测"→"无"，观察结论置信度变化
4. **时序反转测试**：反转关键事件的时序，检验因果方向是否被反转
5. **范式外测试**：在完全不同的分析范式下检验结论，评估跨范式稳健性
6. **综合鲁棒性评分**：基于5项测试结果计算综合鲁棒性评分

### 决策规则

| 测试结果 | 鲁棒性评级 | 行动 |
|---------|-----------|------|
| 5项全部通过 | 高鲁棒性 | 结论高度可靠，可进入决策依据层 |
| 3-4项通过 | 中鲁棒性 | 结论较可靠，需标注脆弱环节 |
| 1-2项通过 | 低鲁棒性 | 结论不可靠，需补充证据或修改结论 |
| 0项通过 | 极低鲁棒性 | 结论不可用，需重新构建论证 |

### 输出规范

```yaml
robustness_stress_test:
  conclusion_id: "CON-001"
  tests:
    extreme_parameters: {result: "pass/fail/conditional", detail: "详情"}
    assumption_removal: {result: "pass/fail/conditional", core_assumptions: ["核心假设最小集"]}
    evidence_downgrade: {result: "pass/fail/conditional", confidence_at_lowest: 0.0-1.0}
    temporal_reversal: {result: "pass/fail/conditional", detail: "详情"}
    paradigm_shift: {result: "pass/fail/conditional", alternative_paradigm: "替代范式"}
  robustness_score: 0-5
  robustness_rating: "high/medium/low/extremely_low"
  fragile_points: ["脆弱环节"]
  recommended_actions: ["建议行动"]
```

### 穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整5项压力测试 | 所有测试可执行 | 完整6步，输出鲁棒性评分 |
| L2 部分3项测试 | 部分测试无法执行（如范式外测试不可行） | 执行可得测试，缺失测试标注"未执行" |
| L3 极端参数+假设移除 | 仅可做2项核心测试 | 做极端参数和假设移除测试，标注"仅核心测试" |
| L4 单项快速测试 | 时间/资源仅允许1项 | 做假设移除测试（信息量最大），标注"快速测试" |

## 14. 内化方法论：证据独立性检验（MC-170 Evidence-Independence）

### 方法论原理

证据独立性检验的方法论基础是：**多条独立证据的联合支持力远大于多条相关证据——因为相关证据可能共享同一错误来源，导致"虚假的强支持"**。当多条证据实际上来自同一信息源或受同一混淆因素影响时，它们看起来各自独立支持结论，但实际上只提供了一次支持。这一方法论之所以必要，是因为最常见的过度自信来源于"证据数量幻觉"——看到5条支持证据就认为结论很可靠，但若5条证据都来自同一来源，实际支持力只有1条。

### 执行步骤

1. **证据来源追溯**：对每条证据，追溯其原始来源（数据源、研究团队、方法论）
2. **同源检测**：检查是否有证据共享同一原始来源
3. **依赖检测**：检查是否有证据因果依赖于另一条证据
4. **共因检测**：检查是否有证据受同一混淆因素驱动
5. **独立性评分**：对每条证据标注独立性等级（独立/部分独立/依赖/同源）
6. **有效证据计数**：仅计独立证据数量，重新评估结论支持度

### 决策规则

| 独立性等级 | 判定 | 处理方式 |
|-----------|------|---------|
| 独立 | 不同来源、不同方法 | 全部计入有效证据 |
| 部分独立 | 部分共享来源或方法 | 计为0.5条有效证据 |
| 依赖 | 一条证据因果依赖另一条 | 合并为1条复合证据 |
| 同源 | 来自同一原始来源 | 合并为1条证据，标注"同源" |

### 输出规范

```yaml
evidence_independence:
  evidence_list:
    - id: "E-001"
      source: "来源描述"
      independence_level: "independent/partially_independent/dependent/co_sourced"
      related_evidence: ["关联证据ID"]
      relationship_type: "same_source/causal_dependency/common_cause/none"
  effective_evidence_count: 0
  raw_evidence_count: 0
  independence_ratio: 0.0-1.0
  adjusted_conclusion_support: "重新评估后的结论支持度"
```

### 穷尽重试策略

| 重试层级 | 条件 | 替代方案 |
|---------|------|---------|
| L1 完整独立性检验 | 证据来源可追溯 | 完整6步，输出有效证据计数 |
