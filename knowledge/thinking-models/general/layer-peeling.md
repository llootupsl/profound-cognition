# 逐层剥离

> 知识来源: MC-162 逐层剥离 (Layer-Peeling)

## 方法论原理

层层剥落分析的方法论基础是：**复杂问题的核心真相往往被多层表象、惯例和假设所包裹——如同洋葱，必须逐层剥去外层才能触及核心**。与第一性原理的"追问为什么"不同，层层剥落侧重于"识别并移除遮蔽层"——每一层遮蔽可能是一个行业惯例、一个未经检验的假设、一个过时的范式。最常见的分析失败不是"没想到"，而是"想到了但被表层惯例遮蔽了"——行业惯例和思维定势形成了自动过滤机制，阻止分析者看到核心问题。

## 执行步骤

1. **表层识别**：识别问题最外层的描述框架和惯例性解释
2. **表层移除**：暂时搁置表层解释，追问"如果这个解释不成立呢？"
3. **次层识别**：在移除表层后，识别下一层的假设和框架
4. **逐层剥落**：重复步骤2-3，直到抵达无法再移除的核心层
5. **核心层验证**：对核心层做公理验证（参照第一性原理的公理验证标准）
6. **重建分析**：从核心层出发，重新构建分析框架

## 决策规则

| 剥落结果 | 判定 | 行动 |
|---------|------|------|
| 剥落3层以上才抵达核心 | 问题被深度遮蔽 | 需警惕行业惯例的系统性偏误 |
| 每层剥落后结论变化显著 | 表层遮蔽严重 | 核心层结论与表层结论差异大，以核心层为准 |
| 剥落2层后结论不再变化 | 遮蔽较浅 | 核心层与表层差异不大，可适当简化分析 |
| 无法识别下一层 | 已抵达核心或分析能力不足 | 做公理验证，若通过则为核心层 |

## 输出规范

```yaml
layer_peeling_output:
  available: bool
  problem: str
  layers:
    - level: int
      description: str
      assumption: str
      removed: bool
      reason_for_removal: str
  core_layer:
    description: str
    verification_status: "verified/unverified"
    conclusion_shift: str
  rebuilt_framework: str
  degradation_note: str
```

## 穷尽重试策略

| 级别 | 条件 | 方案 |
|------|------|------|
| L1 | 可识别多层遮蔽并逐层移除 | 完整6步，输出核心层和重建框架 |
| L2 | 部分层次无法识别 | 对可识别层做剥落，不可识别层标注"层次不明" |
| L3 | 仅可识别和移除表层 | 做表层质疑，标注"仅表层剥落" |
| L4 | 无法做层次分析 | 重新表述问题，标注"无层次分析" |
